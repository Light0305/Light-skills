# light-write

`light-write` 是用于科研论文起草、润色和一致性检查的写作技能，当前版本 **0.3.0**。它吸收了 [nature-skills](https://github.com/Yuan1z0825/nature-skills) 中 `nature-writing` 与 `nature-polishing` 的任务区分和证据约束思路，并重新组织为可独立使用的通用工作流。

## 能做什么

- **起草与论证重构**：根据作者提供的研究问题、结果、方法、笔记或已有段落，组织论点并撰写指定章节。
- **润色与翻译**：改善学术表达、压缩冗余、按要求调整结构或进行中英互译，同时保护研究事实和证据边界。
- **论文一致性检查**：核对跨章节术语、数字、研究对象、分析定义、引用与主张强度。
- **可选期刊适配**：用户指定目标期刊或风格后适配表达；具体投稿要求依据当前官方来源核实。
- **LaTeX 与 PDF 交付**：完整稿件默认交付可编辑 LaTeX 源文件和实际编译、检查过的 PDF；自带双栏、单栏模板，未指定栏数时先让用户选。用户提供 LaTeX/Word 模板则优先按其模板交付。
- **论文级工作流**：对长文使用来源、主张—证据、术语和重复数值账本；对结果重构提供主文/图注/方法/补充材料的分配与压缩审计。
- **论文类型适配**：区分实证研究、方法/技术论文、综述/证据综合、理论/假设论文和方案类文章，避免强行套用实验论文模板。
- **跨领域模块**：通过领域、体裁、精确 venue 的分层路由加载按需指南；当前首批领域模块均为 draft，尚无专家审核或模型质量评测。
- **可复现评测设计**：提供固定配置、盲评、严重错误统计和修订成本记录规范；自带合成案例仅作结构回归，不是质量证明。
- **合成案例**：提供不含真实研究或引用的微型案例，展示从证据账本到段落、主张校准和结果分配的过程。

图形、图表、图像或 graphical abstract 的制作与编辑不属于本 skill；请交给科研流程中的作图 skill。这里可以基于用户给出的材料撰写图注或正文中的图表说明。

## 持续项目与修订

同一个项目的一篇核心论文使用一个 `Write/PAPER-0001_工作标题/` 工作区，转投、返修和草稿版本继续留在其中。局部改句子直接处理，不要求先建项目、补全台账或填 JSON。

- 续作先用有关 Memory/Workflow 找回上下文，再读取实际分析、文献、选刊简报和稿图；保留原生 Analysis 核验结果及警告，不把旧记忆当新证据。
- 接入 Journal 1.1 时区分“作者/授权目标决定”与“证据就绪”，保留文章类型、出版路线、投稿阶段和未核政策；目标暂定仍可做通用论证与提纲。
- 来源更正后，复核实际受影响的标题、摘要、正文、图注和回复信；先重读判断，再记录新版。Figure 源文件继续由 Chart/Diagram 管理，Review 修复要关联受审稿件版本并待实际复核。
- 已要求保存或继续项目即授权必要的范围内文件更新。Word/PDF 交付借助可用文档/构建工具实际生成并检查；Word redline 使用真实修订记录。

可选 `scripts/audit_manuscript.py` 读取 `templates/manuscript-packet.json` 所定义的版本凭据，核对列明文件的 SHA-256、主张文字锚点和人工选定的保护字符串。它不写文件、不自动更新哈希；只查声明范围，不能认证语义、引文准确性、科学有效性或投稿就绪。草稿有待补/冲突主张时，即使文件核对通过也会保留警告。详见 [项目衔接](references/project-integration.md) 与 [可选稿件核对契约](references/manuscript-packet.md)。

## 安装

将整个 `light-write` 目录安装到 Claude Code 可发现的 skills 目录，保留 `SKILL.md`、`references/`、`modules/`、`templates/`、`scripts/` 及其引用的规范文件；推荐复制完整包，例如：

```text
<project>/.claude/skills/light-write/
```

也可以按你的 Claude Code 安装方式放入用户级 skills 目录。只复制 `SKILL.md` 而不复制 `references/` 会导致按需指南缺失。安装后可通过请求“起草论文讨论部分”“润色这段论文”“检查全文术语和结果是否一致”等任务触发。

## 建议提供的材料

按任务提供已有信息即可，不必填满清单：

- 目标章节、论文类型、目标期刊/读者、语言、篇幅和输出格式；
- 研究问题、方法、结果、统计量、图表说明、限制和作者确认过的结论；
- 必须保留的术语、缩写、数值、引用标识或表达；
- 允许的编辑程度：仅语言修订、压缩、局部重组或实质性论证重构。

## 输出方式

完整稿件及排版文件任务默认交付 **LaTeX 源文件 + 编译后的 PDF**：

1. **用户提供 LaTeX 或 Word 模板**：优先使用用户模板，保留其格式、栏数、引用与原生结构；Word 模板按 Word 文档流程处理。
2. **已有稿件项目**：沿用已采用的模板和栏数，后续修订不反复询问。
3. **没有模板**：使用自带的 **双栏** 或 **单栏** 通用 LaTeX 模板。用户未指定时，写稿前先询问“这次使用双栏论文版，还是单栏稿件版？”，收到选择后再写，不静默默认双栏，也不自动生成两份。

双栏版为 A4、10 pt，标题/作者/摘要通栏、正文双栏；单栏版为 A4、11 pt，与双栏版共享排版风格。两者均为通用模板，不冒充任何期刊官方模板。新项目可将源文件放在 `Write/PAPER-0001_工作标题/latex/`，PDF 放在相邻 `build/`；用户路径与已有布局优先。

只改一句话、提纲、一致性检查以及明确要求纯文本/Markdown 的任务仍直接交付所需文本，不额外询问栏数或建整篇工程。完整章节起草时可附简短提纲和主要主张—证据对应；局部修改不强制附表，不隐瞒会造成误导的事实冲突。

模板初始化和编译示例（先取得用户的栏数选择，只运行对应初始化命令）：

```bash
python scripts/latex_project.py init "<论文工作区>/latex" --layout double --language en
python scripts/latex_project.py build "<论文工作区>/latex"
```

单栏使用 `--layout single`；中文或中英混排使用 `--language zh`。默认 XeLaTeX，编译需要 TeX Live/MiKTeX 中的 latexmk、相应引擎和 biblatex/biber 等依赖。脚本拒绝覆盖非空源目录，编译后还须渲染 PDF 并实际检查，不能把源码存在当作 PDF 已完成。详细规则见 [模板与交付](references/latex-output.md)。

版式预览：[双栏 PDF](templates/latex/previews/double-column.pdf) · [单栏 PDF](templates/latex/previews/single-column.pdf)。预览内容仅为模板说明及明确的作者信息占位，不是研究稿件；源模板以 `templates/latex/common/` 共享资源初始化。

## 科学诚信与边界

- 不编造数据、样本量、统计结果、方法、机制、文献或 DOI。
- 不把相关性改成因果性，不把预测/模拟结果写成机制证明/真实部署，不无依据夸大新颖性、普适性或优越性。
- 保留单位、数值方向、比较基线、p 值、区间、否定、限定语、引用对应关系及重要限制；输入冲突时标出并请作者确认。
- 对缺失信息用具体占位符标记，不用领域惯例猜补。用户给出的引用不会被默认视为已核验。
- 期刊硬性要求与写作建议分开；不能核实时不声称规则当前有效。
- 本 skill 负责稿件文本；新研究分析、文献检索、图源修改、独立同行评审和投稿操作交给相应流程。文件交付可调用适用的文档/排版工具，不能把尚未构建或核验的文件称为完成。

## 文件结构

- `SKILL.md`：技能入口、分流规则和核心边界。
- `references/`：起草、润色、章节操作、论文类型、工作账本、结果分配、证据完整性、一致性审查、期刊适配和合成案例指南。
- `modules/`：领域模块目录及静态索引。当前有七份 draft 起始指南，不代表七个领域已覆盖或验证。
- `standards/`、`templates/`、`schemas/`：领域/venue 模块规范、贡献模板和机器可读数据契约。
- `tests/cases.jsonl`：仅用于 smoke/regression 的合成开发案例；评测协议在 `standards/evaluation.md`。
- `scripts/validate.py`：离线结构校验器，不调用模型，也不评测文风/科学质量。
- `scripts/audit_manuscript.py`、`scripts/text_metrics.py`：可选只读稿件核对与指定文本范围计数，不是自动科学审稿。
- `templates/latex/`、`scripts/latex_project.py`：双栏/单栏通用模板、按已选版式初始化和实际编译；编译通过不等于视觉检查或科学核验通过。
- `CONTRIBUTING.md`：模块扩展、评审、数据权利和许可证说明。

## 架构与当前覆盖

通用核心负责起草、润色、证据保真、一致性；领域模块处理证据形态和论证习惯；体裁指南区分文章任务；精确 venue 模块只承担适用范围内的官方要求和编辑建议。路由见 `references/module-routing.md`。交叉学科稿件可组合相关规则；未覆盖领域回退到通用核心，不虚构专业权威。

首批指南为 computing、life-sciences、clinical-health、physical-sciences-engineering、social-behavioral、mathematics-theory、humanities。它们是待专业贡献者审阅的草案，不是全部子领域的顶尖写作保证。当前未内置 Science、Cell、CVPR 等精确 venue profile；CCF A 是分类，IEEE 是出版体系，不能当作单一文风。

成熟度为 draft → reviewed → evaluated；evaluated 只表示存在限定范围评测证据，是否达标需看报告。当前所有模块 review/evaluation 记录为空。

## 校验与评测

在 `light-write` 包根目录运行：

```bash
python -I scripts/validate.py
python -B -m unittest discover -s tests -q
```

纯文本写作无需外部运行时；模板初始化/编译辅助脚本和贡献者校验使用 Python 3.10+ 标准库，实际 PDF 编译另需 TeX 环境，视觉核验另需 PDF 渲染工具。校验器检查目录、元数据、路径、模块/案例关联及数据契约的已实现子集，不是完整 JSON Schema 引擎。可用 `--run` 校验另行生成的记录；不会生成或运行模型输出。

实际评测协议见 [standards/evaluation.md](standards/evaluation.md)。开发案例在 [tests/cases.jsonl](tests/cases.jsonl)，人工场景见 [tests/scenarios.md](tests/scenarios.md)。已进行一轮包含真实模型调用、上游对照和改后复测的合成开发评测，保留输入、输出、哈希及匿名模型审阅，见 [评测报告](evaluations/2026-10-27-pilot/REPORT.md)。尚未开展领域专家盲评或顶尖水平验证；该轮结果不能推广到所有领域、长文或其他模型。

历史评测新增了论证推进与正文语气指南，明确篇幅上下限及中文汉字计数，并细化数学参数依赖表达。第一轮改后完成14份正文复测，亦暴露了工程和人文任务的退步；最后针对这三题的领域修订已写入，但7次计划调用均遇额度耗尽，仍待复测。复测题目已用于修改，应视为回归案例。`scripts/analyze_pilot.py` 会写派生汇总，不能把它当只读命令直接重跑已归档历史；需要复核时先使用隔离副本并显式配置其 BUNDLE。`scripts/run_pilot.py` 的生成/审阅动作会调用本机 Codex 并消耗其额度，不能把它当离线结构检查，具体限制见原报告。

0.2.0 升级增加项目衔接、稿件核对、明确口径的汉字/空白分词计数，以及评测失败/中断记录保护；完成离线回归与隔离的 Analysis→Journal→Write 原生交接测试，详见 [该轮升级记录](evaluations/2026-11-06-upgrade.md)。该轮没有新增独立模型写作质量评测或真实科研课题验证，不改变七份领域模块的 draft 状态。长度工具只计提供的纯文本范围，不解析 Markdown/TeX，不代替期刊自己的字数口径。

0.3.0 增加默认 LaTeX+PDF 交付、用户模板优先、写稿前单/双栏选择及两套通用模板。已在本地执行中英文两种栏数的 XeLaTeX 编译与页面检查，并用显式合成样稿检查 biber、交叉引用、脚注和跨页通栏表格。54 项离线测试覆盖初始化选择、保留已有源工程、编译失败、旧 PDF、缺少工具、未解析引用和待视觉核验状态等路径；这些检查不构成新的模型写作质量评测。
