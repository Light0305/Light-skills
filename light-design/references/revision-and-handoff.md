# 设计修订、来源与执行交接

## 恢复与修订

先读本次采用的 idea_id/version、design_id/version、execution_scope、原设计及有关协议；有 Memory / Workflow 时核对有关决定、已失败的方案和当前任务。一个项目围绕一篇核心论文或一项软著及关联成果推进，设计版本是同一研究的演变。

实质改变独立单位、主比较、终点、分配、排除、分析/判定规则或采用资源时，在同一 PROT 的新 v02 等目录保留新版本，记录 history 的前一版本、触发证据、具体变化、理由与是否已经接触有关结果；同步维护真实 design.version。只改目录名不会更新科学身份。保留旧计划、旧协议及已有批次；不把旧结果重标为按新计划得到。

若改变的是问题、机制或目标贡献，回到 Idea 核查相关文献和主张；若代码/测量实现出错，先回 Experiment/Analysis 修复；若多个解释在原设计下给出同样观测，先改 Design。有效性未核对前不能把异常数值判成科学阴性。

确认性规则在查看对应结果前固定。已看过数据上的修改如实记为探索或偏离，可为后续独立验证建立新计划；写入 history 或保存指纹不等于完成公开预注册。

## 来源跟随实际证据

- 上游导入保留所选证据的 source_file/source_sha256，并对实际直接来源记录输入指纹；选中论文已声明 pdf_sha256 时核对其 PDF。已不一致的来源在创建输出前停止。
- 只跟随所选依据和声明的 PDF 身份，不递归扫描整库；未引用的其他主题或未来资料不因缺失而阻断当前 pilot。
- 本轮 `design.sources` 的本地来源用 path 和小写 SHA-256 的 sha256；相对 path 在当前工作区内解析，外部来源用绝对路径。当前就绪范围所用的 verified 证据需有非空、匹配的本地来源；路径以外的 URL 来源仍由宿主核对，不联网认证。
- 尚未使用的未来本地来源可以缺失并给提示；已有指纹明确冲突属于来源漂移，需要处理。旧来源缺绑定的提示应由宿主复核，不能把当前新哈希当作曾经阅读一致的证明。

哈希只约束字节，不证明题名/DOI 真实、原文蕴含主张或科学判断正确。上游上下文快照也不等于正文备份；旧原文和来源版本继续按 Literature / Idea 约定保存。

## 准备范围与交接

`ready_for_pilot` 只覆盖 execution_scope 内明确的 pilot 及其依赖；后续研究的数据、样本量和门槛可仍待确认。`ready_for_execution` 覆盖本版全部实验。两者均要求当前范围内的资源、任务、验收、质量失败和结果判定足够明确；结构检查不能识别所有遗漏或无科学内容的文字。

交接前检查 design.json、plan.md 和协议的一致性。就绪时 plan.md 必须非空；模板占位、错误科学解释或与 JSON 不一致仍由宿主实际审查。

```text
python "<design-skill>/scripts/design_bridge.py" verify --workspace "<PROT/v01>"
python "<experiment-skill>/scripts/experiment.py" init --design "<PROT/v01>" --out "<EXP>" --max-runs <实际次数上限> --max-wall-seconds <实际时间上限> --budget-basis "<依据>"
```

预算来自实际最小范围和用户已有授权；未知时继续可独立完成的计划，不伪造数字。init 冻结 context/design/plan 和实际 protocols 文件，并保存其指纹；它不自动完成 Design 检查、运行代码或建立额外的设计冻结文件。外部原文/数据不因被路径引用就被复制进批次，应保留其受控版本和位置。

本轮已用真实 Experiment 初始化接口验证交接字节与协议保留，未启动 run。后续执行就绪与真实研究结果仍由相应阶段检查。

## 回给 Memory 与 Leader

给 Memory 留存“为什么选这个单位/对照/终点/阈值”“资源限制怎样影响主张”“为何修订和何时重启”，引用实际设计版本和来源。给 Leader 返回当前完成范围、就绪范围、输入版本、产物、已做检查、未决条件和下一步依据。专业原件保留在 Design，不以记忆或 Workflow 的状态代替原计划。
