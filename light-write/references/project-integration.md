# Manuscripts in a continuing research project

Use for project drafting, substantial revision, or a real stage handoff. A local edit can proceed from the supplied passage. Package resources are relative to the installed skill; research paths belong to the actual project, never to evaluation fixtures or a guessed historical machine path.

## Recover the question and the adopted sources

1. Locate the project's README and current manuscript workspace. One project centres on one core paper or a related software/IP deliverable. Revisions, resubmissions, and journal changes stay within the same paper workspace.
2. If Memory exists, read its current context and task-relevant decisions, caveats, and source references; use available memory tools when helpful. Read relevant Workflow dependencies if present. Neither record establishes that an analysis is valid or a task is complete.
3. Read the actual materials governing this request: study records/plan, adopted analysis and findings, relevant literature, current manuscript, Journal brief, figures, and review issues. Record read scope and unavailable material. Do not require absent upstream skills to perform an otherwise answerable local task.
4. Resolve discrepancies against the governing records. Do not prefer the newest-looking filename, Memory summary, or AI-generated draft by default. Ask for a decision only if an unresolved factual conflict changes the requested output; continue independent supported work.

The author can enter directly with existing text, data, theory, proof, or interpretive material. No mandatory Literature→Experiment chain, universal empirical template, JSON packet, or new project initialization is needed.

## Adopt Analysis and Journal without erasing their limits

For a native Analysis handoff, use its available read-only verify operation against the actual workspace, inspect the adopted report/findings and input versions, and retain its warnings. A file digest alone does not run native verification. Carry through descriptive/exploratory/confirmatory status, retrospective plans, synthetic validation, exclusions, uncertainty, competing explanations, and validity limits. “Complete” is a workflow state, not a scientific quality score.

For Journal, read the real brief and selection evidence, not only a remembered journal name. Check the exact article type, publication route, submission stage, source dates, and pending requirements. In version 1.1, target authorization and evidence readiness are separate; see `references/journal-adaptation.md`. No selection packet or selected journal is required for generic drafting. An author's direct target instruction remains usable even when some policies still require verification.

Make a compact major-claim plan before substantial prose: what is established, what is interpretation, what is planned, and what lacks or conflicts with evidence. Interpretation is welcome when argued from the material and bounded; uncertainty should not erase the contribution. Do not turn a proposed experiment into a completed result or silently convert exploratory evidence into confirmation.

## Save the requested deliverable

Default location: `Write/PAPER-0001_工作标题/`, respecting an existing layout or explicit user path. Suggested files are proportional, not a checklist:

- `outline.md`, `claim-evidence.md`, `terminology.md`, and an adopted-version reference to the Journal brief when useful.
- `sections/` and `drafts/v01/` for actual text and subsequent revisions. Save a new revision for a material review/retargeting handoff; normal edits in an active working draft need not create a new folder on every keystroke.
- For the default manuscript route, `latex/` holds the authoritative editable source, metadata, bibliography, and section files; `build/main.pdf` is the compiled output. Follow `references/latex-output.md`: a supplied LaTeX/Word template wins, an adopted layout persists, and otherwise the user must select single/double column before drafting. Do not keep conflicting Markdown and LaTeX copies of the manuscript. A revision can retain this structure within its existing version directory.
- `build/` for actual generated deliverables, `supplementary/` for actual supporting material, and `submissions/` or `rebuttal/` only when needed.
- An optional `manuscript-packet.json` beside a saved draft if file/claim links would help repeated handoffs; see `references/manuscript-packet.md`. It records adoption, not independent evidence verification.

The request to create/save/continue the deliverable authorizes its necessary in-scope updates. Do not request permission again for routine reversible work. Keep unrelated research files and older reviewed/submitted versions intact. Do not copy large data or the whole literature library to Write.

Deliver the requested artifact first. Default manuscript delivery includes editable LaTeX source plus an actually compiled and visually inspected PDF, using `references/latex-output.md`. Explicit text-only requests and supplied LaTeX/Word templates override that default; preserve the template's native structures and build method. Do not promise a file merely because Markdown or TeX exists. Record tool limitations and anything not actually checked. A native Word redline requires actual tracked changes.

## Iterate with Figure, Review, and research

| Change or request | Action and return |
|---|---|
| Figure/caption mismatch | Inspect the adopted figure and source/QA notes within available scope; correct supported caption/reference wording. Send actual plot or diagram changes to `light-chart`/`light-diagram`, referencing figure ID/version and required evidence. |
| Review issue | Locate the reviewed manuscript version and exact issue. Revise only the authorized scope; record the fix location, supporting source, and remaining disagreement. Return the revised version for recheck; “edited” does not automatically close the issue. |
| Missing analysis or experiment | State the missing comparison/estimate/control and why the claim depends on it. Hand back to Analysis/Design/Experiment as appropriate, with existing finding/claim IDs and uncertainty. Do not run new research or invent results merely to finish prose. |
| Changed contribution, target, or hard constraint | Reassess framing and affected venue requirements; route back to Journal or research when needed. Keep the prior target and draft history. |

Figure data and editable originals stay in Figure. Link the adopted version; copy a fixed submission artifact only when required, recording its source. Write can compare scientific labels, values, caption coverage, and cross-references; this does not constitute a full visual/figure-science review. Unread images remain unchecked.

## When an adopted source changes

1. Preserve the old adoption record and prior reviewed/submitted draft.
2. Identify the actual changed analysis, paper, figure, or journal rule. Use native verification where applicable; do not silently rebuild or overwrite an upstream export.
3. Trace affected major claims and dependent title/abstract/results/discussion/conclusion, captions, supplementary text, and response letter within the available material. State the scope examined; do not claim automatic discovery of every dependency.
4. Re-read the changed source, decide whether the claim still holds, revise or mark the gap, then create the new adoption record. Merely refreshing hashes can leave scientifically wrong prose unchanged.
5. Recheck the changed scope and return relevant Figure/Review/Journal questions with the exact revised version.

## Return useful project context

At a material handoff, give Memory the adopted paths/IDs/versions, decisions and rationale, unresolved evidence/author choices, failed approaches, and conditions for resuming. Use the available memory workflow; if absent, provide a sourced delta for later capture rather than inventing Memory internals. Return actual completion/blocking status and dependencies to an existing Workflow plan. Never mark review, scientific validity, or submission readiness complete from file presence or a passing checksum.
