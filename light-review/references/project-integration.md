# 项目恢复、采用版本与问题回流

用于持续项目、跨阶段交接或改稿复核。局部审一段、一道证明或一张图时直接完成有关范围，不要求先建 Memory、Workflow 或整套 JSON。

## 从上下文回到实际材料

一个项目围绕一篇核心论文或同源软著/专利。先读本轮目标和相关 Memory 条目，恢复研究问题、已采用稿/图、重要限制、旧 LR 问题和作者决定。回到实际专业文件确认身份与适用性；记忆是导航，不能作为原研究的独立证据。已有 Workflow 用于查交接和依赖，completed 不证明科学有效、问题已关闭或当前文件未变。

优先区分本轮被审版、作者活动草稿和已投稿版。文件时间最新不等于已采用，不能混用旧图、新正文和不同数据批次。材料冲突时记录冲突和判断范围，用可支持部分先工作；必要的身份信息不清才问作者。

| 可得输入 | 接入与边界 |
| --- | --- |
| Write 正文/源文件/可选 packet 1.0 | 用实际采用版；packet 有则运行其原生只读 auditor，查看漂移与未决主张，再读正文和科学来源。不强制已有稿件补包。 |
| Analysis 报告/主张/原生交接 | 有可用原生 verify 时使用真实接口，再检查估计对象、独立单位、排除、分母、区间和适用条件。保留探索/确认及合成验证身份，不把运行成功当结果可靠。 |
| Chart 图、图注、数据/代码/QA | 有 QA 时按当前接口运行 `scripts/source_binding.py <figure.qa.json>`；记录 `exports_only` 或 `exports_and_recorded_sources`。仅核对已记录文件，不能代替看真实图、检查映射/统计或证明独立审图；旧 QA 不补造历史来源。 |
| Diagram 原生图/导出/科学说明 | 看本轮实际导出；可用原生检查时检查原生文件。组件清单、截图和字节哈希都不能单独证明对象可编辑或科学关系正确。 |
| Journal 已采用目标/brief/packet | 区分作者目标决定和证据准备状态。涉及当前政策时核查实际精确期刊、文章类型及官方来源；旧模板和推荐不等于当前授权或政策。 |
| 旧 Review 报告/packet | 读原问题与关闭条件，核对当前采用版本；原快照保留当时身份，不自动证明今天的材料仍适用。 |

这里的工具位置从当前安装发现，不假设其他技能必须相邻；用有关技能的实际契约，不拼凑一个通用 verify 命令。无法运行就明确记录，只完成可支持的检查。

## 按根因修复与复核

给问题保留 LR ID、被审稿/FIG/分析版本、证据定位、影响、最小修复、关闭条件和必要依赖。按 [交接指南](handoff-and-recheck.md) 将任务交到 Write、Chart、Diagram、Analysis、Design/Experiment 或 Journal；不要在 Review 中另复制一套可编辑研究成果。

先修根因再改下游表述。分析或数据更正后，重新判断承重主张及已知关联图、图注、正文、补充和评审结论；不能仅更新哈希、继承旧 ready 或把范围缩小写成新增证据。尚未确定原因时先保留诊断假说，不将路由选择当作已证明归因。不会自动发现全项目所有依赖。

有实际修订再生成新评审轮次；旧报告、冻结副本和问题历史保留。复核具体受影响位置，摘要改了但结论仍保留强主张就保持 addressed/open。只做局部复核时即使该问题关闭，也不能据此声明全文或投稿已就绪。工具一致性与科学充分性分别报告。

## 接回 Memory 与 Workflow

本轮结束时只保存实质增量：评审/packet 与稿图版本、LR 状态、关闭或排除依据、改判理由、仍未检查部分、失败经验和下一步。使用已有 light-memory 真实接口并引用专业原件；工具不可用时留有来源的增量供接续，不手写伪事件。来源被替代或更正时标出受影响记忆，不能只改其指纹。

已有 Workflow 接收真实完成/受阻状态及依赖。Review 只审查时交清可执行任务；用户已授权修订则推进有关修复并返回复核，不以发出 handoff 代替实际完成。对外投稿、申请和第三方上传仍按会话真实授权处理。
