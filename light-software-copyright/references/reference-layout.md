# 三份 DOCX 的参考排版

根据用户提供的功能说明、软件代码、软件说明书提取通用版式参数，不把私人样例文件随包发布。
默认参数见 [three-document-layout.json](../assets/three-document-layout.json)；其他用户指定模板优先。
排版参考不能提供新项目的功能、权属、完成日期、代码、截图或软件环境事实。

| 元素 | 默认版式 |
|---|---|
| 页面 | A4纵向；说明文档四边25mm，软件代码四边20mm |
| 页眉 | 软件全称及实际版本，宋体8pt居中；代码另有真实 PAGE 域 |
| 正文 | 宋体12pt，1.5倍行距，首行24pt，段后0 |
| 标题 | 全部黑色000000、黑体；功能说明主标题22pt；一级15pt、二/三级13pt |
| 主标题下划线 | 沿参考保留一条细蓝线4F81BD；代码正文不添加标题线 |
| 层级间距 | 标题段前10pt、段后6pt，与后段连排 |
| 图注 | 宋体10.5pt加粗居中，段前4pt、段后10pt；图保比例且与图注相连 |
| 说明书封面 | 软件名26pt、版本20pt、文档类型22pt；已知的真实权属可写，未知则省略 |
| 代码 | Consolas8pt、中文宋体后备，固定12pt行距；原行不截断，必要时量测缩至不低于7pt |

标题颜色遵从用户2026-11-07的明确要求，覆盖参考中的绿色；采用的排版参数版本为1.1。

功能说明从标题和功能正文开始；说明书独立封面后以原生分页属性进入正文。
步骤用原生有序列表，表格为原生表格且表头重复；不复制样例手打序号与空行撑版。
代码不加封面或文件名标签行，不让这些标签占用真实50行映射；文件顺序/定位在内部源行清单。
超长代码行不能通过裁切、省略、伪造新行或缩到无法阅读来“解决”。

新 case 的 delivery_profile=three-documents；旧 case 无该字段按旧单项命名/布局续作，
不静默重写旧材料。显式 --kind bundle 始终采用三份路线。
采用参数存入 case 的 layout-profile.json；与当前参数不同时工具拒绝静默替换，
应人工检查后在新材料修订目录采用新参数，不改动历史交存版本。

实际 Word 字体替换、分页、代码页数、图表大小、页眉和域需真实打开或转换后检查。
参考版式不是交存合规模板；封面、截图占页、正文行数和文档节选按实际提交规则另核对，
不能以生成了三份或样例排版相似认定常规文档行数及全部登记条件满足。
程序内部每50原行一页不证明 Word 实际每页50行；确认与 source-pages.json 一致后才可记录。
自绘 PDF 与 DOCX 独立生成，不能冒充 Word 转换件。短材料查看全部页；长材料根据最长行、
跨页、前后节选连接、图表和末页确定检查范围并如实记录，不用稀疏抽查声称逐页完成。
