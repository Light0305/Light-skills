# 写成真实软件文档

## 先选材料类型

默认两份叙述性文件各司其职：functions.json 的 document_type 固定为“功能说明”，
按已实现能力、用户场景、入口、输入限制和结果组织；manual.json 按软件形态选择下述
操作/用户/使用/设计说明书。最终固定文件后缀为“软件说明书”，封面显示实际文档类型。
不要只换标题交付两份相同正文。features 用 function_heading 和 manual_heading 分别关联
两份正文；同一模块可在两份中承担不同说明深度。

操作/用户手册适合围绕使用过程表达的软件。设计说明书适合无界面算法程序、SDK、接口服务、
嵌入式或结构逻辑更能体现软件的项目。选一种适合实际软件的文档作为主要鉴别材料；
用户指定的材料类型优先，在缺少证据时指出需要补充的内容。

没有通用的“至少 15 页”“最好凑到 60 页”要求。小软件写完整即可。
先写完整底稿；若超过一般交存页数，再形成有对应关系的前后节选版。

## 操作手册

建议骨架是软件概述、使用条件、开始使用、按真实任务组织的主体章节、错误与处理、必要的
输入/输出说明。只保留有用章节；无账号功能不添加注册登录，无安装步骤不编造安装向导。
不强制存在“相关文档”“术语表”或尚未编写的配套设计/测试文档。

一项核心功能应说明：使用前提、进入入口、关键输入及约束、操作顺序、可观察结果。
实际存在且重要的异常应说明触发条件和恢复办法。不同任务的重点可以不同：
查询突出过滤条件与结果字段，录入突出数据约束，计算突出参数和输出含义，审批突出状态变化。
不要每章机械套五个相同标签，也不要排斥真正清楚的步骤列表和参数表。

示例（仅说明文字质量，不得直接用于无此功能的项目）：

> 在“导入记录”页选择 UTF-8 编码的 CSV 文件。首行须包含 sample_id 和 measured_value。
> 点击“检查文件”后，预览区列出有效记录与错误行。存在缺失列时不会写入数据；按提示补齐
> 表头后重新检查。确认预览无误再点击“保存”，返回记录列表可查看本次新增条目。

每个按钮、提示和字段都应有界面、源码或已确认说明支撑。不把上面的示例变成通用功能。

## CLI、库和科研软件

CLI 写实际命令、工作目录、必需参数、输入格式、小型可重复样例、输出路径/字段、错误码。
没有运行过的命令标注“据源码整理，待运行验证”；不要编造成功日志。
SDK 写初始化、公共调用方式、数据类型、返回结构和异常；服务写接口路径、鉴权、请求响应
与状态约束。科研软件还应交代数据预处理、参数适用范围、随机种子/数值精度、结果文件含义；
不把论文结论、受试者数据或训练集内容当作必须交存的程序正文。

## 设计说明书

可按总体架构、模块职责、接口与数据、核心流程/算法、运行设计、异常与约束组织。
架构图和流程图由真实实现推导，明确是设计示意。图中模块名称要能对应源码，不能为了显得
完整增加支付、消息、权限、备份等实际不存在的组件。算法写处理流程和边界，不必披露与
鉴别材料目的无关的敏感数据；关键技术不能仅剩“系统进行智能处理”。

## 截图与图表

为关键操作列简短取证任务：页面/命令、前置状态、要展示的动作和结果、对应章节。
可以自动取证，也可以使用用户提供的图片。来源记录包含软件版本、采集来源、场景说明、
文件哈希；用户旧图先核对适用版本。保存原图，脱敏另存副本，说明遮盖范围。
截图无真实数据时使用明确标注的样例；不要生成仿真截图冒充运行证据。

图应可读、保持比例、带图注并紧邻解释。图片不足不妨碍先写草稿；若该操作依赖截图说明，
正文保留 `【待补图：具体页面及状态】`，不能把带此标记的材料称为已完成。
无界面软件可用实际命令输出、数据流程图、接口示例，不以截图数量作为通用门槛。

## 正文与渲染输入

`functions.json` 和 `manual.json` 的 `sections` 使用 `heading`、`level`、`blocks`，支持：

| type | 内容 |
|---|---|
| paragraph | `text` 普通段落 |
| steps | `items` 字符串列表 |
| table | `headers` 列名、`rows` 二维列表 |
| code | `text` 实际命令/接口示例，长行需检查 |
| image | `path` 材料目录内相对路径、`caption`、`provenance` 来源说明 |

全称/版本不在正文输入里维护副本，渲染器从 `case.json` 生成标题和页眉。
删除无证据的夸大句、同义反复、模板残留和制作过程用语，如“为通过软著审核……”；
保留操作需要的专业术语，不以“去 AI 味”为由改变事实或掩饰 AI 使用。
