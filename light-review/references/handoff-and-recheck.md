# 接入与修复闭环

## 接 light-write

上游接口从当前安装的 light-write 入口及 `references/project-integration.md`、`references/manuscript-packet.md` 查找。直接稿件始终可审；可选的稿件 packet 1.0 绑定 paper_id/revision、实际来源、主张锚点和保护字面值。存在时按原生 `scripts/audit_manuscript.py <packet>` 只读核对，查看 warnings；退出 0 也不证明论证、引文、图面或研究有效。不要将 Review packet 的冻结副本当作 Write packet 的相对路径基准：原生检查从实际写作工作区执行。

按实际可得材料接入：

| 上游产物 | 本阶段用法 |
|---|---|
| 最终正文及源文件 | 确认被审版本、主张位置和最后导出的提交文件 |
| source / claim–evidence ledger | 作为线索回到原始来源复核，不能将其标记直接继承为 verified |
| 术语、数值与研究事实账本 | 定向核查跨章节漂移；账本冲突也作为输入冲突处理 |
| 未决占位符、作者决定、限制 | 显示还缺什么；未解决的文稿也可以做有边界的预审 |
| 任意作图环节的最终图表、图注 | 单独检查图的真实内容及与正文/源数据的对应 |

不必等所有材料齐全才能开始，但不能把资料不全的预审称为全部通过。用户只给文件时可建立材料清单；需要可重复复核时再使用冻结工具。

## 问题交给谁

| owner | 适用任务 | 交接中需要明确 |
|---|---|---|
| `light-write` | 正文、论证范围、说明、跨章节一致性 | 原位置、允许保留的事实、具体修改目标、关联位置 |
| `light-chart` | 真实数据图、区间/尺度、数字表及绘图实现 | FIG/采用导出、面板、真实数据与变换、单位/分母/区间、代码及图注；新的推断回 Analysis |
| `light-diagram` | 方法/机制示意、组合图的科学表达与原生编辑 | FIG/版本、科学关系、原生文件、组件与标签；数据面板保留 Chart 真实导出 |
| `figure-workflow` | 旧记录或外部作图流程的兼容标签 | 不因标签旧而丢问题；按根因转给实际图形负责人 |
| `light-anaysis` | 用已有数据重新估计或检验解释 | 估计对象、独立单位、已有数据、问题假设、预期判别标准 |
| `light-design` | 对照、可识别性、抽样或判别条件不足 | 原设计与版本、受影响主张、最小判别要求；先确认设计再进入新执行 |
| `light-experiment` | 必要新增实验/仿真/计算 | 对应承重主张、最小设计与判别条件；由实验流程确定可执行计划 |
| `light-journal-select` | 目标/文章类型不匹配、政策变化或转投 | 实际科学范围、目标与作者决定、已核实的具体要求；不是模型自行决定换刊 |
| `author` | 材料、版本、伦理、贡献或范围决定 | 不能由模型猜补的具体事实与选项 |
| `specialist` | 关键专业方法/证明无法充分核实 | 明确到方法、假设或推理步骤，附已完成检查 |

这些名字是交接标签；没有对应技能也可给人执行，不把安装其他技能当作运行前提。内部评审报告应直接包含可执行任务，而不是只说“建议使用某技能”。新实验优先经过研究设计确认，不由评审脚本执行。

## 复核状态

- `open`：问题未解决。
- `addressed`：已有修改或作者说明，仍未检验是否充分。
- `verified`：实际重新读/查了修改和关联材料，关闭检验满足。
- `dismissed`：证据证明原问题不成立；记录依据，不能悄悄抹掉旧意见。
- `deferred`：保留待后续处理。必需问题即使 deferred 仍未关闭；可选增强可以推迟而不妨碍就绪。

稳定使用 `LR-001` 等 ID，不因排序变化重新编号。给新问题分配新 ID。问题改类/合并时保留旧 ID 和映射。严重程度只能随证据/主张/影响变化调整，不能为了清空清单降级。

合并后仍保留每个旧 ID，说明合并到谁并给排除/关闭依据；不要把“合并”当作可以直接删除旧必需问题的理由。旧问题已关闭后又受上游更正影响时，可以重新 open，注明触发来源和当前未决风险。

## 修改后的实际工作

冻结或标识新版本，比较旧包与新包。检查作者解释和实际 diff，再读取受影响的最终材料。每条记录旧状态、新状态、新版本位置、关闭检验结果，以及是否影响其他主张或文件。

只在哈希完全相同且适用性未变时继承旧材料的检查记录，并注明原报告/packet；相同文件名不够。针对修改引起的传播影响复查摘要、结论、图表、图注、补充与投稿声明，不强制重审所有无关段落。

文件化复核按 [记录契约](artifact-contract.md) 使用 1.1：`previous_review` 绑定直接前轮；旧 ID 全部保留，新 ID 超过前轮已分配最大值。问题定义、严重度、必需性或关闭条件改变时给 `reassessment` 的理由与本轮证据。关闭使用本轮 `closure_check`；继承未变的已关闭问题还需核对其所引材料、角色和锚点。脚本只检查直接前轮，不递归认证全部历史，也不能从自然语言判断是否借用同一 ID 偷换了科学问题；实际比较仍由评审者完成。

“已经补了实验”只是说明；需检查新方法、结果与对应主张。“我们同意并计划修改”不是完成。新图看起来更清晰不表示底层分母正确。若缩小主张解决问题，要核查强版本是否仍出现在标题/摘要/结论中，并重新判断论文贡献。

不设任意轮次数或必须达到的分数。还有具体必要问题且有材料可解决，就继续；缺作者事实时给清晰交接并保留未决状态。没有必要问题时结束，单列可选建议，不再制造新一轮润色。
