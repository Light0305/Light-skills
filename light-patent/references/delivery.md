# 文件、公式、附图与检查工具

## 交付按用户范围

| 任务 | 正文文件 | 独立工作材料 |
|---|---|---|
| 专利点分析/检索 | 分析或检索报告 | 实际检索记录、文献定位、缺口 |
| 技术交底 | 交底书；要求 Word 时给 DOCX | 支持表、发明人确认事项 |
| 权要 | 权利要求书 | 逐限定支持表、从属关系及范围说明 |
| 完整申请草稿 | 权利要求书、说明书、说明书摘要；有图则说明书附图和摘要附图 | 证据表、检索报告/限制、确认事项、交付清单；行政表仅在请求或确有需要时 |
| 审查意见答复 | 意见陈述草稿、必要修改文本 | 原始支持与修改对照、剩余问题 |

不把技术交底书、自检表、请求书信息确认表都称为法定必交文件。请求书不能用自制表格冒充官方表单；DOCX 是审阅文件，具体电子提交格式需按当前系统核验。

正文与分析可以分文件夹。遵循用户文件名；默认新版本目录，避免覆盖交付。内部分析可用 Markdown/JSON；提供 Word 时保留可编辑来源和实际图件。完整包需清单说明哪些完成、哪些缺失，不能只有标题或占位图就叫完整。

## 图件

黑白、线条清晰、可缩印，标签、字号、箭头和编号一致。流程表达条件与回路，结构图表达实际配合，不能用装饰图替代技术关系。使用可编辑图源（SVG、Mermaid、Graphviz、CAD等）并实际渲染；源代码围栏不是成品附图。

正文、图号、标记表双向核对：同部件同标号，不同部件不混号。图中仅保留必要文字，复杂解释放说明书。不能在没有事实依据时通过生成图片补出内部结构、化学结构或未提供的视图。

有图时摘要附图从说明书图中选择；不规定必须图1。图缺失时在清单标明，不生成写着“待补图”的文件冒充成品。

## Word与公式

先遵从用户模板，通用审阅版采用 A4、黑色正文、清楚的段落层级和可辨识字号。模板字体/页边距不是所有法域的官方合规保证。标题和正文不加入提示词或内部状态；每类正式文件独立输出，除非用户指定合并。

公式用可编辑 Office Math（OMML）。可利用可用文档工具、经过核验的 LaTeX→OMML 转换或直接构造必要数学结构；检查分数、上下标、求和、矩阵、希腊字母和符号定义。不要把纯 LaTeX 文本或公式截图称为可编辑公式。仅有 LaTeX 时先完成可靠转换，失败则说明格式缺口，不偷偷降级。

实际交付 DOCX 前，使用可用文档渲染器生成逐页预览并查看全部页面，修复溢出、缺字、公式错误、图件模糊及不合理分页。不能渲染时明确“已结构检查，未完成版式目检”，不声称完成视觉验证。没有文档专用 skill 时仍可使用下面的独立导出器。

## 独立工具

所有脚本路径相对 skill 根目录；从其他工作目录运行时用脚本绝对路径。输入 JSON 为 UTF-8，文件/图件相对路径基于 `case.json` 所在目录，而不是当前终端目录。

### 初始化

```text
python scripts/init_case.py --title "一种振动事件上传方法" --out ./outputs/案件A
```

生成 `case.json` 和 `work/`、`drafts/`、`figures/`。目录已存在且非空时拒绝，避免混案。初始化记录机器本地带时区时间；用户另有时区要求时按其要求调整案件记录。不会复制源文件或生成假技术内容。

### 审计

```text
python scripts/audit_case.py ./outputs/案件A/case.json --profile application --out ./outputs/案件A/work/audit.json
```

`evidence` 检查材料与特征索引；`disclosure` 再检查交底正文；`claims` 再检查权要、说明书支持；`application` 再检查说明书、摘要及图件。只运行适合任务的档位。`--format md` 可输出易读检查报告。退出码0无错误（可能仍有警告），2有结构/支持错误，1输入不可读或工具错误。

脚本检查 ID/引用、逐限定映射、支持状态、来源文件及可选指纹、原申请支持字段、多项从属规则、正式文本占位、必需正文、图件存在和摘要长度等。**它不判断**推导是否必然、文献是否真正披露、说明书是否实质支持概括、是否充分公开、是否具有创造性或是否存在侵权。

### 导出

```text
python scripts/export_case.py ./outputs/案件A/case.json --kind application --format both --out ./outputs/案件A/交付v1
```

`--kind disclosure|claims|application`；`--format md|docx|both`。标准库可导出 Markdown；Word 额外安装 `requirements-docx.txt` 中的 `python-docx`。导出前运行对应结构审计，有 ERROR 则不生成包。不会以“忽略错误”开关放行无支持权要。语义检查仍由撰写者完成。

支持标题、段落、表格、图件和 OMML 公式，不是通用 Markdown 转换器，不自动套机构模板。复杂版式或公式用可用文档工具处理。工具导出的 Word 清单默认标记版式待目检，不伪造已验收状态。

图件 PNG/JPEG 会嵌入 Word，原图复制进交付包；矢量图源可另外保留。`equation` 块必须有有效 `omml` 才能导出 Word，仅 LaTeX 可导出 Markdown。正式 Word 不包含证据 ID；`支持表.md`、`检查报告.json` 和 `交付清单.json` 单独保存。已有非空输出目录拒绝写入；失败暂存目录被保留便于诊断，不覆盖旧文件。

### 续作核对

```text
python scripts/export_case.py ./outputs/案件A/case.json --out ./outputs/案件A/交付v1 --verify
```

只读比较 case、交付清单列出的文件，以及显式声明的本地 sources 和存在的图件/图源。
新交付清单版本为1.1，case 结构仍是1.0；旧清单无 source_inputs 时明确降为
recorded_case_and_exports_only。退出码0为已记录字节相同、2为发生变更/缺失、1为输入或工具错误。
不会扫描整个研究项目或替未落地网页生成内容指纹，不认证技术支持、新颖性、法律结论、
版式或提交状态。变更后重读受影响依据，另出新目录，不能只刷新清单哈希消除旧证据失效。
