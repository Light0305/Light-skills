# Working ledgers for manuscript projects

Use compact ledgers to keep a multi-section task coherent. They are reasoning aids, not a requirement to expose a large table in every response. Save them when useful for an authorized manuscript/project deliverable; that request supplies permission for necessary in-scope updates. A chat-only task needs no saved ledger or separate permission round.

## 1. Source-of-truth inventory

Before substantial drafting, list the supplied sources that govern the manuscript:

| Source | What it governs | Verification/status | Conflicts or caveats |
|---|---|---|---|
| Author-confirmed study summary | Core question, design, primary result | Author-provided; not independently verified | — |
| Results table or analysis output | Values and analysis population | Supplied output; check internally against prose | Conflicts with draft n in Methods |
| Current manuscript | Existing wording, citations, section structure | Source text supplied by user | Citation accuracy not independently checked |

Do not treat an AI-generated summary or earlier draft as authoritative when it conflicts with original study records. Ask which source prevails only when it changes the manuscript. Mark source status explicitly; access to a document does not equal external verification.

For a continuing project, include adopted analysis/finding IDs, file versions and locations, the applicable Journal brief, and figure versions where they govern the prose. Preserve native verification warnings. Memory helps find and interpret these records; it does not replace them. On source change, revisit affected claims before accepting a new fingerprint; see `references/project-integration.md`. An optional machine-readable receipt is described in `references/manuscript-packet.md`; the table remains sufficient for many tasks.

## 2. Claim–evidence ledger

For a substantial draft or reconstruction, track major claims rather than every sentence:

| Claim | Evidence/source | Status | Scope/qualification | Planned location |
|---|---|---|---|---|
| What the manuscript proposes to assert | Specific supplied result or source | Author-provided / verified / inference / missing | Population, conditions, uncertainty, limitation | Section and paragraph |

Use this to detect unsupported claims, duplicate claims with no distinct role, and changes in strength across sections. If a claim's support is missing, weaken it only when the narrower claim is still clearly supported; otherwise use an evidence-needed marker.

## 3. Terminology ledger

For a whole manuscript, translation, or recurring technical vocabulary, record canonical forms and unresolved choices:

| Concept | Preferred term | Avoid/variant | Definition or context | Status/decision owner |
|---|---|---|---|---|
| Name of a construct or measure | Canonical manuscript form | Source variants | Operational definition | Author confirmed / provisional / ask author |

Apply the preferred form consistently and define abbreviations at first use, following the target journal or discipline where applicable. Preserve official names, registered terms, gene/protein nomenclature, mathematical notation, and author-mandated wording. Do not silently collapse terms that might denote distinct constructs. Flag naming collisions and ask the author to decide only when the distinction is scientifically material.

## 4. Numerical and study-fact ledger

When editing or comparing sections, track only facts that recur or are likely to drift: population/sample counts and denominators, group names, time points, primary outcomes, units, effect estimates, intervals, p values, and analysis labels. Record the authoritative source and location. If values conflict, preserve both as a conflict until the author identifies the source of truth; never settle it by plausibility.

## 5. Keeping and presenting ledgers proportional

- A local sentence edit usually needs no visible ledger; verify protected facts against nearby source text.
- A full section benefits from an internal claim–evidence list and, when terminology recurs, a short term list.
- A whole manuscript or major restructuring should use ledgers for terminology, recurring numerical facts, and major claims; show a compact subset only when it helps the author review decisions.
- Update the ledger after an approved terminology or claim change, then check all affected occurrences and dependent sections.
- Do not infer independent validation from an internally consistent ledger. It records provenance and editorial decisions; it does not establish that research data are correct.
