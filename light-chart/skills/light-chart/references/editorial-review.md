# 视觉审查：程序通过之后还要做什么

适用于实质改进论文图、复杂组合图，或用户认为“像默认模板”的情况。综合 SciPilot 的实际读图闭环、FigMirror 的参照/感知/修订方法、nature-figure 的证据架构。这不是自动评分器。

## 看哪些图

1. 原始参考：打开用户图或视觉库中相近原图，辨认值得保留的结构和应修正的缺陷。截图模糊时不精确声称字体名称、线宽。
2. 整页：缩到计划的物理宽度，看第一眼先注意到什么。180 mm 画布在超大窗口里清楚，不证明印出来也清楚。
3. 面板：查看原分辨率 PNG 与最终 PDF 栅格预览，核对坐标、误差、个体点、图例与短标注。两种输出的字体排版可能不同。
4. 灰度：看关键组是否仍可分；需要时加形状/线型。这不等于完整色觉模拟。

参考图和新数据结构不同时，比较可迁移属性，不把像素相似度当科学质量。不为与参考一致而删除新类别、补原图星号或改变真实横坐标间距。

## 先解决哪类差距

先辨认交付用途：论文图、教学说明页和幻灯片不是同一种成品。论文图中出现介绍性大标题、解释副标题、来源/方法长脚注时，先移到独立图注，再重排图面；不要把展示页的文字层级当作论文质感。表格默认检查 LaTeX 结构与数值，不能用绘制表格图片充当新增图件。

| 问题 | 低质量症状 | 优先修订 |
| --- | --- | --- |
| 要判断什么？ | 每指标一格，却看不出中心比较 | 分配不同证据角色，合并重复证据，保留关键限制 |
| 主次清楚吗？ | 九种亮色、大图例、粗轴线一起抢眼 | 位置/标签承担身份，只保留必要强调色 |
| 数据还是模板占空间？ | 空图例列、介绍标题/副标题/长脚注挤占数据区 | 说明移入 caption，压缩重复图例，重新安排数据区 |
| 信息能直接对应吗？ | 每根柱都要回图例找名字 | 行名+区间列，或少量系列直接标注 |
| 可横向比较吗？ | 不同轴/每列独立色标制造差异 | 可比面板共享尺度；不可比的明确区分 |
| 细节稳定吗？ | 字母不齐、色条随意、同组换色 | 统一物理锚线、图例尺度和语义映射 |
| 统计诚实吗？ | n=3 画平滑分布，汇总值伪造原始点 | 只画实际提供的数据层，保留缺失和来源限制 |

先改影响推断和整页阅读的 1–3 个问题，再改小数、线宽和点大小。不要先抠像素却保留错误的总体结构。

## 具体记录修改依据

记录应像这样具体，但只能写实际发生的内容，不能复制示例冒充审查：

```text
参考依据：共享方法顺序，三个指标并列；未继承截断柱轴。
初稿问题：方法名占一整列图例，每个指标都要重新查颜色。
修订：方法行名+三列点/源误差；目标行用同一浅色带定位。
已看：整页 PNG、PDF 渲染、方法名及误差放大、灰度。
余留：源误差定义不足，保留原误差并写入 legend，不称 95% CI。
```

不得虚构“审美 9.5 分”“独立审稿通过”等证据。修改几何、标签、字体或尺寸后，重做受影响的导出、检查和看图。

## 两种记录

- `visual_review`：实际检查的数据对应、文字、裁切、遮挡、可分辨性。
- `design_review`：参照、构图、证据层次、密度、修订和残留问题。可用 `pending / needs_revision / self_reviewed`；写明同一执行者自检。

自动 PASS、自己看过、用户接受、期刊接受，是不同事实。用户否定视觉质量时，回到成图修改，保留前稿比较；不能拿已有通过数解释质量。

## 绑定实际版本并比较

`publication.save_figure(..., source_data=data)` 保存源记录摘要、绘制值/图像快照、标记诊断和当前导出的哈希；`audit_marks()` 包含固定坐标轴的点/线/区间裁切和图例遮挡。Python/R 导出均生成 `.pdf-preview.png`。这些是局部几何诊断，三维遮挡、任意变换和科学推断仍需实际读图。

```python
comparison = compare_revisions(previous_qa, current_qa,
    required_panels=["joint", "top", "right"],
    required_classes={"joint": ["PolyCollection"], "top": ["Rectangle"]})
record_review("figure.qa.json", inspected=["figure.png", "figure.pdf-preview.png"],
    observations=["这里写实际看图发现及保留的具体事实"], previous="draft.qa.json",
    required_panels=["joint", "top", "right"])
```

改动文件后旧审查失效；缺少当前 PNG/PDF 渲染检查、必要构造缺失、源数据未绑定、数据/身份变化未解释时拒绝直接标为完成。`unresolved` 记录待修改问题；确定为有意裁切或非阻断问题时，resolutions 逐项给 code/panel/mark/decision/evidence。科学上必要的构造或样式改变，可用 justified_changes 将比较器返回的具体变化逐项映射到实际理由。类名/数值快照不能证明复杂构造在视觉上正确，必须同时看最终图。R 的原生 ggplot 层比较见 [r.md](r.md)，自定义 grid 回调仍需专门适配。Python 三维快照记录真实网格面片/空间轨迹，而非相机投影后的二维点，未知几何类型明确拒绝比较。

Python 修订也比较实际坐标范围、轴标签/单位和标量色彩编码（色标范围、归一化、发散中心及采样色带）。数值未变也可能改变阅读含义，需说明修改理由。旧快照缺少这些字段时明确提示编码信息可用性变化，不把缺少记录推断为实际坐标或单位发生变化。

常规小图按需要修订即可。复杂参考适配可用 `figannot.py` 保存并排图、局部反馈和有上限的迭代记录，见 [reference-style.md](reference-style.md)。不强制引入独立 agent；有明确授权且确有需要时再分工。
