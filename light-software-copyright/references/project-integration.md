# 持续项目、同源成果与回传

本项目可以是一项软件，也可以是一篇核心论文及其同源软件/专利。只有用户需要时进入软著；
“论文已有代码”不自动说明其构成完整可登记软件，不把论文章节拼成不存在的界面或功能。

恢复有关 Memory 的目标、已确认事实、软件版本、未决权属、排除范围和上次问题，
再回读实际源码根、入口、依赖、构建说明、界面/命令、冻结代码和当前文档。
Workflow 是工作状态，不是实现证据；旧截图、记忆或 hash 一致也不等于功能已运行。

与科研技能接入时：

- Experiment / Analysis：定位真实代码与采用版本，区别程序、自有改动、依赖、模型权重、
  数据、运行结果和论文素材。--project 指源码根，--case 指 SoftwareCopyright/SWC 工作区。
  不能把整个研究项目或 Figure/Write/Memory 输出扫描成交存源码。
- Write / Figure：可引用真实功能说明和图源，不能把科研示意图当作软件运行截图。
  文档中的性能/准确率仍须真实实验支持，不因登记材料而升级研究结论。
- Patent：共享代码版本、真实技术说明和公开时间线，分别判断著作权事实与专利披露/保护对象。
  不自动发布源码、提交材料或决定申请顺序；敏感内容按实际任务核查。
- Review / 补正：保留受审三份文件及内部输入、问题 ID、通知来源和实际修改。
  实现错误回代码；说明错误修正文；名称或版本变化同时核对页眉、文件名与源页。

functions.json 与 manual.json 分别写正文，features 同时用 function_heading/manual_heading
定位两份材料；evidence 指实际项目文件、可选真实行段和指纹。渲染时另记录这些文件实际字节，
防止未填写可选 sha256 的功能依据变化后仍沿用旧稿。新版本先重读，不能只刷新指纹。
单改功能说明只重建它；改源码需重扫、复核范围、抽取并重建受影响材料。补图先核图版本。

完成本轮后由宿主按需保存 Memory 增量：采用的源码/材料版本、功能和证据边界、
未决登记事实、排除及第三方依据、检查范围和下一步；更新已有 Workflow 的实际文件与问题。
事实与源码仍留专业工作区，不复制进记忆作为新的独立证据。原生工具不自动执行这些衔接。
