# light-write 跨领域写作开发评测

日期：2026-10-27，日本时间。状态：上游对照与第一轮修订复测已完成；第二轮领域修订的生成请求因使用额度耗尽而失败，待复测。

本轮实际生成并保留了 **42 份正文**：修改前 light-write 14 份、上游 14 份、第一轮修改后 light-write 14 份。另有 **7 次额度失败**，没有正文，不进入写作质量或长度评分。两组比较各由两次独立上下文的匿名模型审阅覆盖，共 **112 条单篇评分、56 条成对偏好**。这里的“独立”仅指新上下文调用，并非不同模型或独立专家。

这批短任务表明，两套指南都能支持基本的跨领域写作和证据校准。上游在计算机视觉引言和数学表述上有可借鉴的优势；light-write 在部分工程、临床、定性研究和人文任务上得到较多偏好。第一轮改动改善了一些具体问题，同时在三个题目上出现退步。样本与评分的区分度不足以证明整体优胜或任何领域的顶尖水平。

## 设置与可核查范围

- 七类领域，每类各一个起草和一个润色任务，共 14 题；材料均为原创合成材料，主要要求 75–190 英文词的短段落，另有一题 180–260 汉字的中文讨论。题目保存在 [cases.jsonl](cases.jsonl)。
- 起草对照 `nature-writing`，润色对照 `nature-polishing`。测试读取本机安装版本及所需的 `nature-shared` 核心和按条件选定的参考文件。manifest 声明的版本分别为 1.5.0 和 6.6.0；未取得对应 Git commit，以文件哈希标识实际测试版本。
- 使用本机 Codex CLI 0.164.0，`--ignore-user-config`，`medium` 推理档位、只读环境、新进程、空工作目录。两臂使用相同任务和共同提示。将选定的指南原文装入输入；没有测试自动发现 skill、自动选文件或工具协作。
- 每个任务/版本仅生成一次，没有无 skill 基线。共同提示已经包含只使用所给材料的约束，因此不能从本轮推断 skill 相对裸模型的净提升。
- 生成期间没有逐次指定模型。一个同配置的独立探测调用显示 `gpt-6.1-sol`、`openai`、`medium`；JSON 生成日志未逐次返回解析后的模型名。原始运行记录保留 `effective: null`，不据探测结果追填每次调用的模型身份。继承的完整系统提示也未被记录，复现实验仍存在限制。
- 两次匿名审阅使用同一 CLI 默认模型系列，按七题成批。评审看到研究材料、任务和评分要点，看不到 arm、skill 文件或修改建议。顺序固定随机化，映射与评分分别保存。模型自我偏好、批次效应和相同模型导致的相关性仍然存在。
- 原始输入、输出、事件、时长、token 用量、文件清单和 SHA-256 均保留。冻结前后指南见 [初始 light-write](snapshots/light-before/SKILL.md)、[第一轮修订](snapshots/light-after/SKILL.md)、[第二轮待复测修订](snapshots/light-after2/SKILL.md)。

预先记录的试验设置见 [registration.json](registration.json)。未假装进行作者修订时间测量、领域专家审核或真实论文测试。

## 修改前与上游的比较

每领域有两个题目，每题有两次审阅，因此下表每行合计四个成对判断；这些判断不是四份独立研究样本。

| 领域 | 偏好 light-write | 偏好上游 | 平局 | 本轮具体观察 |
|---|---:|---:|---:|---|
| 计算机/视觉 | 0 | 2 | 2 | 上游引言更好地组织了背景依赖问题、方法和原分布/背景变化下的性能代价；润色接近 |
| 生命科学 | 2 | 1 | 1 | 两者均正确处理生物与技术重复、扰动/救援与机制证据；讨论的偏好有分歧 |
| 临床健康 | 2 | 0 | 2 | light-write 更谨慎地区分未提供混杂控制信息与已确认未控制；两者均漏掉中文长度下限 |
| 物理/工程 | 3 | 0 | 1 | light-write 的模型—样机关系及具体后续试验略受偏好，属于局部写作差异 |
| 社会/行为 | 2 | 0 | 2 | light-write 的定性发现更像正文；两者都有重复解释主题共存的问题 |
| 数学/理论 | 0 | 3 | 1 | 上游更清楚显示阈值对参数的依赖，并明确受限无限集合猜想的量词范围 |
| 人文 | 2 | 0 | 2 | 两者均能保留叙述者/作者之分和另一种解释，light-write 部分解释收束更有力 |

合计为 light-write 11 次、上游 6 次、平局 11 次。按题而非按评分票数看，两次审阅一致偏好 light-write 的题目有 3 个，一致偏好上游有 2 个，一致平局 3 个，其余 6 个有分歧。因此不把 11:6 当成稳定胜率或显著优势。

两次模型审阅都没有标出预设严重错误类别中的实例。这只表示未被当前审阅识别，不能证明没有科学错误。许多分项均分接近 4/4，存在明显的评分天花板，本轮主要依赖具体意见定位问题。原始分项见 [aggregates.json](aggregates.json)，逐篇理由见 [decoded-reviews.json](decoded-reviews.json)。

## 已完成的第一轮打磨与复测

实际改动：

1. 新增 `references/argument-and-prose.md`，要求段落推进明确的证据关系，并区分稿件正文和材料来源说明。
2. 在入口补充语言、段落/句数以及长度上下限检查，区分英文词与汉字；不为了达到下限重复限制或添加结果。
3. 数学指南明确阈值对固定参数的依赖，可以解释性地写作 `N(ε, θ)`，同时保持量词顺序和定理强度。
4. 证据指南区分“没有提供某程序的信息”与“确认没有开展某程序”，避免从缺失信息推断研究事实。
5. 起草和授权的结构编辑接入新指南；评测加载清单相应记录新文件。

在相同 14 题上重新生成，再对改前/改后进行两轮匿名模型比较：13 次偏好改后、6 次偏好改前、9 次平局。按题看，一致偏好改后 6 题、一致偏好改前 3 题、一致平局 4 题，1 题有分歧。题目已用于修改，属于回归证据；每次仅一个输出，不能分离提示改动与随机波动的影响。

| 一致判断 | 题目 | 具体依据 |
|---|---|---|
| 改善 | 计算机引言 | 将 trade-off 变成核心问题，收尾减少未开展评估的罗列 |
| 改善 | 中文临床讨论 | 汉字数从 154 提升到 196，进入 180–260 范围；补充对敏感性分析的条件性解释 |
| 改善 | 定性 Findings | 对正式选择权和实际选择自由的区分更清楚，重复减少 |
| 改善 | 数学引言、数学润色 | 去掉材料管理语气，清楚呈现受限猜想和参数依赖 |
| 改善 | 人文润色 | 在保留另一解释后，以阅读贡献收束，而非以否定性声明结束 |
| 退步 | 工程摘要 | 相同的未匹配比较限制出现在主体和结尾，造成重复 |
| 退步 | 工程讨论 | 后续试验不再明确说出保持其他材料特征可比，提案不如原先具体 |
| 退步 | 人文引言 | 保留了另一解释，但解释性贡献比原段落弱 |

对全部已完成输出，改前两组均为 13/14 满足规定长度，改后为 14/14。英文按空白分隔 token 计算，包含公式 token；中文按汉字计，排除数字、拉丁字母和标点。允许的作者说明以标签启发式排除，故这些是声明过口径的机械检查，不能替代期刊实际计数。首轮审阅把临床两句输出视为满足句数要求；其他格式结论也仅限任务样本和人工/模型审阅范围。

## 运行成本与方法局限

已完成输出的平均输入 token：初始 light-write 27,619，上游 31,240，第一轮改后 light-write 28,768。初始 light-write 约低 11.6%，第一轮改后约低 7.9%。这些用量包含共同系统开销，受手工加载策略影响，只说明本轮输入成本，不能等同于所有实际使用中的节省。

平均生成墙钟时间分别约为 17.0、17.9、18.1 秒，存在并发和服务负载干扰，不足以证明速度优劣。没有记录货币费用，也没有测量作者修订成本。注册时未明确预计 token 总预算和完整审核 rubric；已记录比较、重复次数、严重错误目标和评分原则，但前瞻性仍不如正式预注册研究。

本轮最主要局限是：合成短题且每领域只有两题；没有无 skill 基线；一次生成；相同模型系列生成和评分；评分天花板；固定上下文而非真实路由；没有长篇或多轮写作、正式 venue 合规测试、真实研究材料与独立领域评审。缺少这些证据时，不应使用“全面超过 nature-skills”或“各领域顶尖水平”的结论。

## 文件审计与后续复现

写作输入不包含 `rubric` 或偏好映射。审阅输入包括评分要点、匿名正文和研究材料，不含 arm 或 skill 路径。原始评分中两处 `domain_approprpriateness` 拼写错误在派生汇总中统一为 `domain_appropriateness`，数值未变，原始数据保留；变更清单见 [review-normalizations.json](review-normalizations.json)。

49 份运行记录均通过当前数据契约、正文/输入一致性、案例哈希和加载指南哈希检查。7 份失败记录仅通过记录完整性检查，绝不视为有效写作样本。完整结果计数见 [summary.json](summary.json)，长度明细见 [mechanical.json](mechanical.json)。

在项目根目录运行以下离线命令，不会调用模型：

```powershell
python -I scripts/validate.py
python scripts/analyze_pilot.py
python -m unittest discover -s tests -p test_pilot.py
```

额度恢复后，以下命令会消耗本机 Codex 额度。它保留原始失败记录，创建新尝试目录，使用冻结的 `after2` 指南继续选定题目；不需要也不应覆盖已有快照：

```powershell
python scripts/run_pilot.py generate --phase after2 --workers 1 --retry-errors --cases engineering-draft engineering-polish humanities-draft clinical-draft clinical-polish computing-draft math-polish
python scripts/run_pilot.py review --phase after2 --workers 1 --cases engineering-draft engineering-polish humanities-draft clinical-draft clinical-polish computing-draft math-polish
python scripts/analyze_pilot.py
```

若仍返回额度错误，运行器会停止派发后续未开始任务，已在运行的请求可完成；不循环重试。失败或空输出不会被装进审阅包。重试后的模型配置可能随本地默认值改变，需记录并披露，不能假定跨时间完全相同。

下一轮质量研究应先冻结候选版本，加入无 skill 基线、全新的跨项目长材料和独立领域评审，重点核实本轮明确暴露的技术引言、参数化数学表述、工程摘要重复与人文解释力度。先用这些现有题目排除回归，再以新材料评价泛化；不要继续在同一组公开题上微调后宣传分数。
