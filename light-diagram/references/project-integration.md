# 项目证据与修订衔接

适用于持续项目、图文协作、评审修图与换会话恢复。单次提示词或局部修图只采用与请求有关的内容。

## 从实际项目恢复

先确定真实项目及本次 FIG，读取已有 Memory 中有关决定、限制、采用版本、失败尝试与来源；有关 Workflow 可用于找到待办和依赖。随后打开真正的科学原件及当前图源，核对适用范围、版本与路径。Memory 和 Workflow 的完成状态都不是科学有效性证明。无需初始化另一套记忆或另一张 FIG。

来源优先使用实际读过的论文段落/图号、设计版本、分析 finding/claim、真实样本图、软件或用户说明。记录读到的范围与定位；不可得材料标明缺口。风格参考只支持视觉处理，不能给新项目提供机制。生成图不能为自己的科学内容作证。原始图片、影像、谱图、数据面板与证据性照片不能被生成图替换。

## 保持同一张图的身份

- 围绕同一篇核心论文或其同源成果，父入口与子技能共用一个 Figure 工作区及 FIG ID；更换工具不另造一张图的身份。
- 先查采用版本及正在运行/结果不明的生成任务，避免重复付费调用；超时不说明服务端未执行。
- 修改保留父版、修改理由、受影响面板/实体/关系以及未修改范围。只改文字也可能改变科学含义；换工具或重导出也可能改变连接与排版。
- 单次局部修图可用已有记录的简明增量。需要可校验交接时用 1.1 handoff 的 revision、parent 与 subjects；不要给每个简单问题强加完整 JSON。
- 科学事实、待检验假设、推断与示意性构型分别标记。颜色、虚实线和箭头的含义写入图意/图注；重复对象保持身份和层位，局部放大标明来源。
- 忠实复现的已知源错误在报告中保留；科学修正版列清改动依据。不能把几何复现检查当作机制有效性的确认。

## 与稿件、选刊和评审往返

进入制图前取本图在稿件中的任务、相关主张、术语、图注、面板引用，以及用户已经采用且与制图有关的期刊要求。若这些材料不存在，按本次范围推进，不要求先选刊或先写全稿。当前投稿格式涉及实际要求时核对官方来源。

| 问题 | 最小反馈及接回位置 |
|---|---|
| 名称、图注或交叉引用不一致 | 给 Write 对应稿件版本、FIG/面板、正确术语及依据；改图后核对两边采用版本。 |
| 连接、方向、层位或组件缺失 | 在当前 FIG 修复，回查源段落/设计/代码；无法确定时记录待核对，不能凭视觉猜补。 |
| 定量面板或统计标注问题 | 给 Chart 真实数据/分析版本和具体问题。混合图只替换采用的数据导出，不让生图重画数据。 |
| 证据不足或研究结论改变 | 指向 Analysis/Design/Idea 的相关问题与现有材料，不为完成图形擅造结果或开展新实验。 |
| 评审提出修改 | 保留 issue、被审图/稿版本、修改位置及复核证据；已修改不等于该问题已验证关闭。 |

回给 Write 的最小材料是采用的 FIG/版本、实际图源与导出、面板/符号/箭头说明、来源和已知边界、需要同步的图注/术语及仍未解决的问题。不是新建第二份图源。投稿要求固定副本时记录其来自哪个已核对版本。

## 变更后的复核与记忆

文件换版时重新读受影响科学输入，判断主张与关键关系是否仍成立；不能只刷新哈希。检查范围包括实际受影响的提示词、场景、原生文件、导出与图注，保留无需重做部分的理由。输入科学结论改变时，标出已知受影响的文字、评审、图和记忆；不声称自动发现了全项目所有依赖。

在实质交接时，给 Memory 有来源的增量：采用路径/版本、关键决定与理由、未决问题、失败教训、编辑边界和恢复条件。按现有记忆工具的真实接口保存；不可用时留下简明增量供后续接入，不凭空手写其内部事件。已有 Workflow 只接收真实完成/受阻状态及依赖。图源与科学原件仍留在各自专业目录。
