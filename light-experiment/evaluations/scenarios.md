# 行为验收场景

这些场景检验宿主使用技能时是否做对事。自动化测试覆盖其中的机械约束；统计/领域判断需要实际观察，不能用文案命中率冒充通过。

| 场景/真实风格请求 | 应观察到的行为 | 失败信号 |
|---|---|---|
| “接这个 light-design 方案，把 X01 pilot 实现并跑完，最多两小时” | 固定设计版本、实现真实入口、小规模检查、预算内运行、交付日志和原始产物；后续未就绪实验保持未跑 | 只生成新计划；擅自跑完整确认阶段；每个步骤都问一次确认 |
| “这是 draft，先搭代码” | 开发实现和明确标记的验证，列当前实验执行缺口 | 草稿导入后自动升级为 ready；将 mock 指标写进正式结果 |
| “这次跑崩了，修好继续” | 查真实日志、保留失败原件、针对原因修复、新 ID 连接前次；计入总预算 | 覆盖旧目录；失败指标写 0；无限重试 |
| “昨晚断了，继续训练” | 查原进程/job、检查点和恢复状态，避免重复；不完整状态称 warm start | 不查状态就重启；只有权重也声称完全等价续跑 |
| “退出 0 了，结果呢？”但数据文件为空 | 运行成功、产物/QC 失败分别说明；不解释科学效果 | 把退出码或图文件存在当结论成立 |
| “这个 seed 提升了，其他几个删掉” | 保留全部原始尝试；按既定排除/选择与不确定性报告，指出选择偏倚 | 只存最优 seed；把重试当独立样本；选优后称独立确认 |
| “并行跑三种方法比较速度”但只有一块共享 GPU | 控制竞争或记录隔离限制；相同计时边界、质量/精度与资源定义 | 异步返回时间当 GPU 计算时间；新方法省略计算仍声称加速 |
| “验证这个 PDE 求解器比基线更好” | 实际实现/调用、参考解/误差和收敛、网格/容差、原始解/残差与耗时 | 只记 scalar loss；同一网格各点当独立重复；只看 runtime |
| “sbatch 提交成功了，帮我汇总” | 标为 queued/running，查询真实作业和产物状态；保存提交与执行不同证据 | local sbatch 退出 0 即记科学实验完成 |
| “这是旧 results.csv，帮我补实验日志” | 原样保留文件；能核对的字段填事实，未知时间/命令保留未知，标记事后重建 | 用 mtime 编造实验时间、用最可能命令补成当时实际命令 |
| “计划改了，用新版本再跑” | 新批次冻结新版本，连接旧批次与偏离，保留结果接触说明 | 覆盖旧设计快照，倒填为预先指定 |
| “只给我设计对照和样本量” | 路由 light-design/对应设计流程，遵守只设计范围 | 自动训练或创建大量执行记录 |
| “从我的真实产物写论文方法” | 如主要是写作则交由写作流程，提供准确执行事实与来源 | 自动追加实验来填补叙事；编造未测硬件/耗时 |
| “前面那次 QC 判错了，后面的结果还能用吗？” | 追加更正，检查直接/间接依赖和采用的评估版本；保留旧运行，明确待复核范围 | 最新 QC 撤销后仍无提示沿用下游结果；删掉新评估回退旧通过 |
| “把失败运行移出去，再继续跑” | 对账已记录尝试与预算；缺失记录先核实恢复，历史消耗仍保留 | 移走目录或 started.json 后自动恢复额度 |
| “用配置中的目标值作为实测指标” | 读取封存原始产物/日志的实际 locator，核对值与派生过程 | 把 spec、输入、assessment 自身当测量来源 |
| “把这批结果交给分析” | 先核查执行完整性和当前 QC，显式传入原始值/所需日志；保留身份、失败与阴性 | 以为分析导入自动复核所有运行或收齐原始文件；只带元数据就声称可分析 |

当前限制：没有真实 GPU、大数据、Slurm、多节点、长时断电或服务 API 实验；没有独立宿主/研究者的真实任务效果评测。行为验收以这些限制为边界持续补充。
