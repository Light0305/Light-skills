# 研究项目记忆工作流

## 1. 恢复当前工作

先定位真实项目，确认 Memory 的项目身份与当前 project.json 相符。Memory 尚未建立时，先读 README、当前阶段原生 brief/报告和用户上下文；能完成局部任务就直接完成，形成足够材料后再初始化。已有其他形式的记忆先保留，通过明确输入逐步接入，不递归吞入整个项目。

`current.md` 是上次生成的导航，可帮助找入口。正式依赖某条记忆前运行只读 context/show，检查当前来源与依赖状态，再回原生文件读取必要范围。上下文较长时按“概要 → 相关条目 → 原始证据”逐层展开；不能因启动时看过摘要就声称完整阅读过原文。

工作记忆至少恢复：研究问题及适用边界；本轮所用 idea/design/批次/分析或稿件版本；重要约束；触发本轮的发现/评审；待决定的问题与下一步。缺一项只影响依赖它的工作，不要求为恢复会话补齐所有项目字段。

## 2. 提取有价值的增量

事件后的宿主整理是核心。保存会影响后续决定、减少重复劳动或解释路径的信息，例如：

- 为什么选这个研究问题、最近工作如何改变贡献定位；
- 为什么采用这个对照、独立单位、终点或停止条件；
- 哪个运行故障已定位、哪些结果无效、哪些阴性仍有价值；
- 哪个分析推翻了旧解释、仍无法排除什么；
- 选刊目标是作者决定还是暂定建议，政策何时需重核；
- 哪条图文/评审问题已修复、为何缩小主张、哪些相关位置受影响；
- 源码登记范围、申请版本、公开时间和待确认权属事实。

不要存逐次工具输出、整个 stdout、所有论文正文或重复流水账。源材料已有历史就保存引用和决定性锚点。失败教训写清触发条件、诊断依据、已经排除的原因、适用边界和再尝试条件，不把单个失败变成普遍禁令。

`fact` 是项目事实；`finding` 是有限研究观测/解释；`decision` 是取舍及理由；`constraint` 是资源或范围约束；`hypothesis` 是待检验押注；`lesson` 是有边界的经验；`question` 是未决；`next_step` 是建议或已授权范围内待办。每类都要有来源，且类型本身不证明可靠性。

## 3. 判断新增、修订还是并存

先检索相同 scope/slot 与相关条目。更新单位是具体意义与适用范围，不是相似字符串。

1. 原文未变、只是重述：不重复写；重试同一次增量使用相同 capture_id。
2. 同一决定明确被修订：新条目引用旧条目 supersedes，给原因和新依据。
3. 旧结论被证明记录错误/依据无效：显式 retracted，保留撤回依据；依赖它的记忆标为待复核。
4. 未决问题确实解决：显式 resolved，保存关闭证据与必要关联；解决问题不自动证明研究成功。
5. 新旧材料矛盾但原因不明：同 scope/slot 并列，显示 conflict；先定位测量、版本、单位和边界，必要时交给相应专业流程。
6. 研究范围不同：分 scope 并存，如不同设计版本/群体/任务。新数据集上的负结果不自动撤回原范围的结果。

依赖传播使旧来源或旧解释失效时，下游条目不会继续被当作可直接复用上下文。宿主重新分析后需要写入新的、引用最新依据的条目；不能仅点击“确认没问题”或刷新哈希清除警报。

depends_on 表示“继续使用本条目需要该前提仍然有效”，不是一般的历史相关性。某次旧故障确实发生过、从旧版本学到的教训，可以通过来源定位和历史引用保留；不要仅因主题相关就让所有记忆依赖所有前版，造成无意义的整项目失效。

## 4. 跨研究和论文循环

“分析要求补对照”的一次记录可以包含：受影响的 finding、为什么需要新对照的 decision、下一步设计问题；原 AN handoff 仍是专业交接。真正形成新设计时再记录采用的新设计版本，实际运行后才记录完成情况。不能用记忆预先填出未来研究过程。

“评审要求缩小主张”保存 REV/问题 ID、旧稿版本、依据和修订决定；修改正文与图后保存新版本引用；复核后再解决对应 question。评审 addressed 与 verified 不混淆。记忆不替代 review.json 的状态，也不反向修写它。

## 5. 既有项目导入与长期维护

有多个版本时先根据当前任务和上下文定位，不能只拿最新修改时间。分阶段阅读当前 brief/报告、原生结构化文件和关键证据，在增量里标出实际核对范围。没有证据的旧总结可以作为来源明确的旧叙述保留，不能提升成 verified_observation。

原生输入保持原地，记忆没有另存所有 PDF/数据的功能。项目整体搬迁后相对引用继续可用；外部文件通过真实项目内清单或版本入口关联。外部 URL 只保存访问日期和实际已读摘录，不联网验证；时效事实设 review_after，实际刷新交给现有检索/选刊流程。

不自动读取所有聊天、监听文件、安装 hooks、运行睡眠整理或跨项目共享。只有实际调用本技能/遵守接入约定并完成写入，才有新的持久记忆。未来需要常驻检索或多用户扩展时，再根据规模实测选择数据库/向量服务；本版的边界不通过“超级大脑”措辞掩盖。
