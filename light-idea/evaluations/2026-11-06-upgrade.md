# 2026-11-06 light-idea 升级与验证

版本：0.1.0 → 0.2.0，JSON schema 仍为 1.0。延续原有证据驱动选题、最近工作比较、反方审查和最小判别验证，重点补齐输入变化、想法修订、旧记录迁移及下游交接。

本轮只更新技能源码包；没有安装外部系统、覆盖旧研究项目或更改全局技能安装路径。所有运行用隔离合成材料，文中方法论文只作设计依据，不充当用户的学科证据。

## 基线与实际复现

原有 37 项离线测试全部通过。先新增 8 个独立回归场景，修改前全部失败，复现以下缺口：

| 缺口及后果 | 处理 |
|---|---|
| 固定优先 screening.jsonl，可能忽略用户后来修改的 CSV | 选较新文件，记录两者；同一时间而关键决策冲突时停止，避免猜测 |
| CSV/JSONL 同时间且互相矛盾时静默采用其中一个 | 对比关键决策，明确要求解决歧义；一致内容可正常导入 |
| manifest 漏掉旧文章，导入器静默接受不完整库 | 核对目录覆盖、重复身份和目录，索引明显不完整时先修复 |
| 导入时不比对 Literature 已记录的 PDF 字节身份 | 选中文献有 pdf_sha256 时检查来源存在与一致性，冲突先处理来源版本 |
| force 重新计算输入指纹后，旧证据仍可能被当作有效 | 推荐的本地证据独立保存实际核对时的 source_sha256；刷新索引不能消除来源失效 |
| force 覆盖 context，丢失旧输入基线 | 保存原始 context 字节到 context-history，维护路径/哈希并检查归档完整性 |
| 改了研究问题却漏升 version，可继续用旧查重通过推荐检查 | 日志同时绑定 version 与科学内容指纹，查重需适用于当前内容 |
| 证据挂某论文 ID，却引用已知另一篇的文件 | 检查已知文件归属；该检查不能判定任意未登记文件来自哪篇论文 |

另补充空白来源文件检查、旧记录可读性、已核对来源不变时继续使用、纯标题整理、实质修订后真正刷新查重绑定、只读命令、同时间一致筛选、独立本地来源漂移及实际 Design 交接测试。

既有合成完整记录和理论研究测试补上新来源/内容绑定，以检验新的推荐契约；没有把基线断言删除来回避失败。

## 科研流程与使用调整

- 项目续作先读相关 Memory、Workflow 和真实来源，恢复已采用版本、被否决路径及重启条件；局部讨论不强制初始化项目设施。
- 一个项目可以比较多个候选，通常围绕一篇核心论文或一项软著及其关联成果取舍。用户已选择方向时围绕该选择核实和改进。
- 分析/执行反馈先判断有效性：实现或分析错误交回对应层次，设计不可判别交给 Design，科学前提受挑战才改 Idea；不能把执行失败直接当科学阴性。
- 实质修改保留旧候选、触发来源和版本历史，重新检查相关文献；不同 DOI 的预印本/发表稿不自动合并，同一研究的多个报告不重复计数。
- 复制、阴性、理论、定性和资源型贡献按其知识价值与判别方式处理，不统一要求新模型或显著性。
- 给 Design 交所选 idea_id/version、来源和查重、预测/竞争解释、最小验证及未决条件；原生接收结果是 draft。给 Memory 保存选择/修订理由、失效前提和重启条件，给 Leader 返回实际范围与下一步依据。

具体契约见 [artifact-contract.md](../references/artifact-contract.md)，版本迁移与闭环见 [revisions-and-handoffs.md](../references/revisions-and-handoffs.md)。

## 方法来源与未验证范围

本轮重新打开 [SciMON 的 ACL 原始记录/摘要](https://aclanthology.org/2024.acl-long.18/) 和 [LitPivot v3 的 arXiv 记录/摘要](https://arxiv.org/abs/2604.02600v3)。前者支持以既有文献比较迭代候选，后者讨论想法与相关文献集合共同演变。来源/内容绑定是本包的工程设计推论；本轮没有重复阅读全文、重审全部外部仓库或复现其系统。

程序仍不能验证证据是否真实蕴含主张、URL 内容是否变化、检索是否充分、差异是否科学上有意义、资源是否真的可用。相同哈希不是阅读或创新认证。旧推荐补哈希/日志前应实际复读复核，不能只重写元数据使错误消失。

待后续真实宿主/整体研究情境验证：已有主意的细化质量、跨主题材料的取舍、碰撞后的实质转向、不同研究类型的贡献、分析有效性回查、换会话恢复以及候选在最小验证后是否仍成立。本轮没有新增独立盲测或测量创新质量、发表率、成功率、时间节约。
