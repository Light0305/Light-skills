# 原始证据、记录与派生关系

## 证据层次

| 类型 | 能说明什么 | 不能自动推出什么 |
|---|---|---|
| 计划/推测 | 打算做、预期或可能原因 | 已执行、原因已证实 |
| 本地工具实际记录 | 命令、时间、退出码、日志和已读取文件 | 隐式依赖全被记录、科学质量合格 |
| 远端系统状态 | 被查询时的真实 job 状态/记账 | 提交命令结束意味着作业完成 |
| 用户/他人报告 | 谁在何时给了哪项说法 | 本轮独立验证了其真实性 |
| 事后重建 | 基于哪些旧文件恢复了记录 | 记录在实验当时已经存在 |
| 模拟/合成测试 | 指定人工问题下的实现行为 | 真实数据有效性或科学发现 |

每条重要事件保留 `event_id / event_type / run_id或task_id / occurred_at / recorded_at / actor / evidence_refs / observation / interpretation / next_action`。发生时间未知填 null；已有文件 mtime 只作为线索，不当作可信实验时间。追加更正事件并引用旧事件，避免悄改先前事实。

## 原始产物最小范围

保留与问题相关、无法廉价可靠重建的记录：完整 stdout/stderr、实际配置、逐样本/实例/重复结果、预测/响应/解/轨迹、失败部分输出、关键 checkpoint 和输入/代码/环境指纹。大型产物按需要索引，不普遍保存所有训练中间张量。项目约束不允许存放敏感原值时，保留受控位置、字段说明、权限与复算途径。

原始层保持字节内容；绘图、清洗、格式转换或去标识化产出新文件。数据字典说明列/键、单位、数据类型、缺失编码、维度、时间和 ID 对应。`null + failure_reason` 表示缺失；真实 0 只表示实际测得的 0。JSON 不写非标准 `NaN / Infinity`，原始程序日志仍原样保留。

文件清单记录相对路径或稳定外部 locator、大小、SHA-256/存储原生内容标识、生成/获取方式和关联运行。外部对象 URI 可被覆盖时补充版本/etag的实际语义；不要把 multipart ETag 直接称为 SHA-256。哈希采用流式读取，不把大文件一次读进内存。

## 追溯一个报告数值

证据路径应能表达：

`主张 C01 → 实验 X01/条件 → R001 的 outputs/predictions.jsonl:sample_id=... → 评价脚本版本与参数 → derived/comparison.csv:row=...,column=... → 报告/图表`

聚合记录包含哪些单位/运行、排除及理由、权重、选择规则、误差/区间的算法与版本。汇总数字不能替代逐单位数据。报告中的显示舍入不覆盖原始精度。跨运行比较先核对划分、指标、预算与质量定义是否一致。

附带工具的 `manifest.json` 是字节完整性清单，`assessment.json` 是宿主的 QC/解释文件；前者不会证实后者的科学结论，也没有第三方可信时间戳或防篡改签名。单文件齐全不意味着完整依赖闭包；源文件快照必须包含真正影响计算的代码、锁文件与评价器。

## 与已有追踪工具合作

- MLflow/W&B/TensorBoard 已有时保留 experiment/run/model ID 和可读离线索引，原始产物以其实际存储为准；不要再运行一份训练来满足目录模板。
- DVC/内容寻址存储负责大数据版本，记录能取回的版本与权限。仓库里的 `.dvc` 文件存在不等于远端数据可访问。
- Snakemake/Nextflow/Make 负责 DAG 时保留 workflow revision、调度日志、实际配置与各 task 对应；不要把重新调用主入口当作无副作用检查。
- 需要互操作归档时可按 Workflow Run RO-Crate 表达 software/action/input/output/agent/time。附带 JSON **没有**宣称符合 RO-Crate；真的导出时使用官方 profile 验证。

默认本地保存，不擅自上传云端、发布结果或发送日志给第三方。不要自动全量导出环境变量、`.env` 或凭证；命令参数也不得内嵌密钥。外部工具的自动上传/自动日志需按用户当前选择配置。
