# 项目证据、采用版本与修订交接

持续项目、从分析出图、稿图协作或评审修图时使用。局部改字、单次出图按请求范围完成，不要求先建立整套科研目录或填写大型交接表。

## 恢复上下文并回到科学原件

定位真实项目及当前 FIG。一项目围绕一篇核心论文或同源成果；同图修订、换 Python/R、改变导出格式都不另分配 FIG。读取已有 Memory 中相关问题、决定、采用版本、限制与失败尝试，再打开它们引用的实际科学材料、当前代码与图。Workflow 可帮助找到依赖和中断状态，不证明分析有效或图已核查；不因旧状态为完成就跳过核对。

从 Analysis 接入时读实际采用的报告、finding/claim、输入与版本；若有原生只读 verify，使用真实接口核查，不能用文件哈希代替它。保留探索/确认、合成验证、独立单位、配对/层级、排除、分母、区间定义、缺失和方法限制。已有 CSV、R 对象、图或代码也可直接进入；不以缺少 Analysis 工作区阻断可支持的任务。

绘图可以计算明确且受支持的描述变换或工作模型量，但须说明计算、输入、假设和核对；不能为贴近参考图擅造显著性、调整效应、未实测分布或额外样本。新的研究推断、模型选择、复杂检验或方法缺口交回 Analysis，必要时再回 Design/Experiment；不是为了完成图形自动启动新实验。

## 保存同一图的实际材料

默认 `Figure/Data/FIG-0001_数据图短名/`，已有 `output/drafts/exports/qa` 原地续作。只保留本次实际使用的文件：简短任务/字段映射、相对路径绘图代码、必要 helper、输入引用或有来源的小副本、图注、导出和核查。大数据和权威结果留原位置。没有参考适配或独立审阅时不制造其记录。

在已有留版方式中保存实质修订，尤其是已被稿件采用、已审或已投稿的版本；可用 `v01/v02` 或独立 basename，不覆盖唯一旧图、旧 QA 与采用记录。普通活动草稿可原位迭代。`save_figure` 本身仍允许同名覆盖，调用者需要先选择正确版本位置；它不是自动版本库。

## 绑定实际输入与导出

Python 例子仅说明接口，路径换成真实任务材料：

```python
report = save_figure(
    fig, "drafts/v02/figure", source_data="inputs/estimate.csv",
    source_files={"code": "plot.py", "task": "task.json",
                  "style": "project-style.json", "caption": "caption.md"},
    size_mm=(180, 120))
```

`source_data` 为文件时自动进入 `source_manifest`；为 DataFrame 时只有数据摘要，没有可回查的磁盘原件。`source_files` 接受一个路径、路径列表或名称到路径的映射；同名文件用不同名称明确区分。只列真实存在且实际使用的文件，不靠加入一个未使用 CSV 来宣称可追溯。

R 沿用 `save_figure_r(..., source_files=c(raw="data.csv", code="plot.R", task="task.json"), data_sources="raw")`。`data_sources` 明确哪些已绑定条目是数据，避免代码或图注修订被当作源数据变化；未指定时保留旧接口的保守全输入签名，不猜文件角色。两条路线都在导出前捕获来源，导出后核对是否变化；来源变动/删除保留失败报告，不刷新哈希将其洗成成功。全部实际导出（包括 SVG、TIFF、灰度预览）与 PDF 渲染绑定本次 QA。灰度只是辅助检查，不能替代色觉检查。

```text
python scripts/source_binding.py drafts/v02/figure.qa.json
```

该命令只读，不运行绘图、分析或更新记录。返回 `recorded_files_match` 或 `stale_or_unavailable`，并声明 `exports_and_recorded_sources` / `exports_only`。退出 0/1/2 分别表示已记录文件匹配、变更或不可得、报告无效。匹配仅覆盖列出的文件，不能认证数据到 artist 的对应、统计正确、图注事实、视觉质量或独立审阅。

旧 QA 没有来源清单时仍按导出核对，不补造历史来源；旧 R 清单只有哈希而无路径时可读，但不可声称已复核原件。文件位置变化时保留旧记录，在读过实际源文件、核对映射并重新检查当前图后生成新的采用记录；不要仅换路径或刷新哈希。清单保存本次本机绝对路径用于精确核对，交付代码和项目导航仍使用可迁移的相对路径/定位信息。

`record_review` 会拒绝已记录来源或导出变动，并声明自检绑定范围。审图 `stage --qa` 先核对来源和实际 draft/PDF 是否对应 QA，之后冻结审阅副本。旧冻结审阅仍描述当时版本；它不自动证明目前输入仍适用。直接审已有图片可不传 QA，此时只保留视觉检查范围，不伪造数据核查。

## 与稿件、示意图及评审往返

制图前读取可得的当前稿件主张、术语、图注、面板引用和已采用期刊要求；没有这些材料时仍完成当前范围。实际投稿要求另核当前官方来源，不从旧模板推定。

| 情境 | 处理与最小交接 |
| --- | --- |
| Write 需要一张支持具体主张的图 | 绑定主张/finding、图和面板任务、实际输入及变换；交回采用 FIG/版本、导出、图注、单位/区间/独立 n 定义与限制。 |
| 图注、数值或交叉引用不一致 | 对照真实结果和采用图修复支持部分，给 Write 具体稿件版本与修改位置；标签修正也需重新导出与核查。 |
| Diagram 混合面板 | 数据面板仍由真实 Python/R 输出。Diagram 引用确定导出，保留比例和标签；不能让生图重画数据。组成整图后重看整体字号、引用与证据对应。 |
| Review 提出问题 | 保存 issue、被审 FIG/稿件版本、受影响面板、修改依据与前后核查，交回明确修订供复核；已改不等于问题已关闭。 |
| 数据/分析更正 | 保留前版，回读更正后的原件，重新判断主张、映射、区间/尺度及图注；标记已知受影响的稿件、图、评审和记忆。 |
| 只需视觉修正 | 保留正确数值、身份、单位和构造；记录有意改动，实际核对未受影响的证据。 |

不自动选最新版；采用时写明实际版本、理由、未决项、核查范围和文件引用。可以用简短图注/采用记录，不另造平行的通用交接引擎。重大科学输入改变后重新判断，不能仅刷新哈希或沿用旧视觉通过；不声称已自动发现全项目所有依赖。

## 将实际增量接回项目

实质交接时给 Memory：FIG/采用路径与版本、相关科学来源、面板含义、决定及理由、未决问题、失败经验、已检查范围及恢复条件。按现有记忆工具接口保存；不可用时留下有来源的增量供后续记录，不手写伪事件。已有 Workflow 接收真实完成/受阻状态与依赖。研究原件、图源和审阅历史留在各自专业位置。
