# 与研究、记忆和同源软件衔接

## 进入案件

围绕本项目的一篇核心论文或一项软件，按实际需求建立 Patent/PAT 工作区；不为了产出数量
拆散一个协同方案。先读有关 Memory 的目标、放弃路线、公开/保密约束、已有决定，再看
Workflow 的当前任务；没有这些入口也可从已有技术材料直接开始。只做局部改稿不强制建表。

随后回原件：Literature 的论文与阅读定位、Idea 采纳的技术假说、Design 实际版本、
Experiment 的代码/运行条件、Analysis 的实际结果及限制、Write 被采用的稿件、
Figure 的真实图源。只把实际采用且已读的材料列为 sources；查到的现有技术另作 prior-art，
领域常识作 context。上游 verify 只核其声明范围，不能代替本案逐限定支持判断。

## 同源成果与公开时间线

论文、软件及专利可引用同一代码提交和实验，但三者保护对象与事实范围各自判断。
不因有登记材料就认定技术方案有新颖性，不因论文实验有效就认定全部实现细节已披露。
软件版本与 PAT 案件身份分开；同一程序不同版本不能混成交存/实施例。

涉及预印本、答辩、仓库发布、演示、投稿公开或软著材料披露时，记录实际版本、时间、
公开对象和可见内容，未知则留问题。实际影响按法域和当前官方规则判断；
不把“先投稿/先登记/先申请”写成适用所有项目的固定次序，不推定存在宽限期。
只整理时间线不代表获准对外公开、申请或提交。

## 修订、审查与更正

- 首次申请前补充的新实验或代码，先读内容并形成真实披露，再决定是否修改。
  已申请后修改，另核原说明书/权要/附图的确切部位；后续结果不自动补成原始依据。
- 收到 Review 或专业审查意见，保留受审 case/稿件和问题 ID；对照实际限定、图式和依据
  做最小必要修改。科学数据或实现错误先回 Analysis / Experiment，不能只润色权要掩盖。
- case、已声明来源或附图变化后，先回读并追查受影响限定，再出新交付目录。
  export --verify 只比对已列文件字节，未列依赖、技术实质与未存网页仍需人工复核。
- 工作完成后由宿主向 Memory 保存少量有来源的增量：采用方案、范围及理由、公开约束、
  源版本、未决事实、变更和重启条件；更新已有 Workflow 的实际产物/问题。
  不以台账 completed 或记忆 verified_observation 宣称可授权。

这些衔接由宿主读取有关技能并执行，不存在一个通用自动提交或 invoke_skill 接口。
