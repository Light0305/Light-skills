# 取舍、反方审查与最小验证

## 先看阻断条件

在比较分数前确认是否能回答问题：核心概念能否操作化、关键数据/材料能否获得、最小测试能否在资源内完成、测试能否区分主要解释、最近工作是否已经覆盖主要贡献。

将资源条件记为 `confirmed / plausible / unknown / blocked`，并给依据。公开网页上写有“可申请”不等于访问已获准；代码公开不等于可复现；有 GPU 不等于预算足以训练。`unknown` 要配最先确认的动作，`blocked` 应暂缓或重设计。

“推荐现在先验证”不等于推荐直接开展完整研究。pilot 所需条件已确认即可推荐 pilot；完整研究仍未确认的资源在计划里单列。不要因完整项目尚有未知而阻止便宜、可解释的早期验证。

## 透明比较

需要比较时可用下面的 0–3 有序尺度；不确定使用 `null` 或范围并说明。尺度是本技能的工作约定，没有心理测量学或发表预测意义。

| 维度 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 知识/实践价值 | 答案不改变任何决定 | 局部便利 | 回答明确未决问题 | 能改变重要解释或实践判断 |
| 相对差异 | 被最近工作覆盖 | 实例/工程差异，意义未明 | 有来源对照的实质差异 | 差异还揭示更一般的原理/边界 |
| 可检验性 | 什么结果都算成功 | 能测但解释混杂 | 能区分主押注与主要竞争解释 | 明确反证路径且误判可控制 |
| 当前可行性 | 关键条件被阻断 | 主要依赖未确认 | 最小测试条件已满足 | 测试便宜且后续路线也清楚 |
| 信息增益/阴性价值 | 成败都不更新认识 | 仅选一个工程配置 | 至少排除一种重要解释 | 多种结果都能清楚改变后续选择 |

分数必须带理由、证据和不确定性。一般不需要加权总分；确需加权时由用户目标确定权重，展示原分与权重敏感性。保留价值高但不确定的探索候选，不让它与低风险主线混成一个平均排名。

## 反方审查

对入围方向找一个会导致“现在不值得投入”的具体理由。检查：

- 最近工作已覆盖；目标收益能由更强简单 baseline 或同等预算解释。
- 同一个观测结果支持多个机制，现有设计无法区分。
- 数据泄漏、选择偏差、共同方法、反向因果或测量误差足以解释主结果。
- 假设在目标条件下不成立，跨领域类比缺少兼容条件。
- 正结果无法推广，阴性结果无法解释，或测试比完整项目还昂贵。

记录“攻击 → 依据 → 方案改变 → 残余问题 → 是否改变状态”。不要把角色扮演的赞成票当成多专家共识。

## 最小验证设计

先写决策：这个测试之后，准备继续、修改还是停止什么？再设计测试。不要把“做出整个系统，再看指标”称为最小验证。

| 项目 | 要回答的问题 |
|---|---|
| 押注与竞争解释 | 为什么会有该现象？还有哪个解释最容易产生同样结果？ |
| 区分性预测 | 哪种结果是两种解释不同意的？ |
| 比较/对照 | 用什么公平比较、负/正对照、反例或对照案例排除混杂？ |
| 观测/指标 | 实际观察什么，是否测到了主张中的构念？ |
| 支持/反驳/不确定 | 事前定义这三种情况；区分效应小与测不出来 |
| 资源与上限 | 数据/设备是否确认，最贵依赖是什么，最多投入多少？ |
| 有效阴性结果 | null 会排除哪种解释？检测灵敏度与执行质量足够吗？ |
| 质量失败 | 哪些错误会让这次测试不能用于支持或反驳假设？ |
| 下一步 | 现在能做什么；继续前还必须获得哪条证据？ |

优先检验最危险且测试成本较低的前提，而不是优先堆组件。成本估计可粗略但必须说明依据；无依据的精确时间/费用只会制造虚假的可行性。

## 各领域的判定重点

- **CS/ML**：固定数据划分、强简单 baseline、调参/推理预算和主要比较；检查污染和时间泄漏。观察单次小提升不能证明机制；必要时用多个随机种子、配对差异及不确定性。pilot 的小样本用于筛选前提，不自动支持最终泛化。
- **实验科学**：以实验单位区分生物与技术重复；设计适当对照，先检查测量/实验是否工作。没有效应依据时先做测量和可行性 pilot，不编最终功效数字。
- **观察/因果问题**：写清目标人群、时间顺序、对比/estimand 和识别假设。横断面 SEM、预测准确率或加入中介变量都不能单独证明因果。若识别做不到，就缩小主张。
- **理论**：写清命题、定义和假设，与最接近定理逐项比较；先查平凡情形、极限情形、最小反例或证明瓶颈。数值例证不等于证明。
- **定性**：提出可被资料挑战的解释，明确比较案例、偏差来源、反例和解释修订规则；不照搬统计显著性门槛。
- **资源/评价**：先验证新资源能否可靠测到目标差异，关注标注一致性、构念覆盖和污染，而非只比较数据规模。

## 状态与退出

`candidate` 是待探索；`shortlisted` 是值得展开；`recommended` 是有依据建议进入明确的下一步；`hold` 是等待材料或关键条件；`rejected` 是已有理由不推进；`archived` 保存历史。

`recommended` 的最低含义：有可核对的支持材料与正文最近工作对照，当前版本完成有边界的多路径查重，差异具体，最小测试有区分力，启动该测试的数据和资源条件已确认。即使字段检查通过，宿主仍需判断内容是否真正达到这些条件。

允许所有方向都暂缓或淘汰。停止理由要可撤销：明确什么新证据或资源变化会重启，而不是用低总分永久否定。缺少关键资源时保留一条可以继续的低成本信息收集动作。
