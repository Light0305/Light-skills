# 决策、投稿顺序与写作交接

## 硬条件使用三态

| 状态 | 含义 | 处理 |
|---|---|---|
| `pass` | 适用证据证明满足 | 进入下一步比较 |
| `fail` | 适用证据证明不满足 | 排除；高适配/高指标不能抵消 |
| `unknown` | 缺信息、来源冲突或资格未确认 | 条件性待核，不能列为已满足所有条件的主投 |

确认“必须”还是“偏好”。未指定的限制不自动增加；单位规则要核实适用版本。作者确实授权你决定某些可放宽条件时，记录选择与理由；不能擅自放宽非授权的硬条件。

范围或文章类型明确不符也应排除，即使未列在用户的硬条件清单。待核和排除分开，不把未知冒充负面结论。

## 推荐顺序

在可行候选内，先比较具体范围、贡献类型、读者和可比研究，再看作者偏好。可使用简单的逐项比较：

1. 本稿的主要贡献在A、B两刊分别会被哪种读者理解？
2. 哪本的主要不利因素可通过真实且有限的写作调整解决？哪本实际需要新增研究？
3. 费用、时限和机构约束的证据哪个更完整？
4. 当“快速发表”改为“最低成本”优先时，首投是否改变？若改变，给出条件分支。

一个候选在重要维度均不差且至少一项更好时，可以说明其优先性；否则保留取舍，不强行算出唯一客观总分。关键未知不能当平均值或零费，也不能通过重新归一化使其获得优势。

如果用户明确要评分，说明维度、尺度、权重来自用户还是工作假设，并展示关键权重/未知事实变化是否改变首位。评分只帮助比较，不是质量鉴定或录用概率。

“冲刺/主投/备选”是相对于该研究材料、作者目标和可接受投入的策略标签。用已有稿件/相近研究说明差距；不从影响因子或分区反推稿件等级，也不为了三梯队齐全而推荐明显不合适的刊。

## 拒稿与转投

先确认投稿状态与作者提供的拒稿理由，区分：

- **范围/读者原因**：更换学术对话或目标期刊，调整论证焦点。
- **普遍科学问题**：设计、比较、推断、伦理或材料缺陷；换刊不能自动解决，列出必须修复项。
- **期刊特定门槛/格式问题**：重新核查新刊适用要求，避免把旧刊规则带入。
- **只有简短拒信**：不要编造编辑真实动机或把拒稿当质量数值标签。

在已经拒稿/撤稿完成后安排顺序投稿；在审时只做规划。一般给首投→下一可行目标→调整触发条件，不必机械从高指标降到低指标。出版商转投邀请是待评估选项，不是录用保证；确认范围、费用与政策后再建议接受转投。

若作者要求咨询编辑，可准备一封简短预投稿咨询草稿，列研究问题、证据、文章类型和适配疑问；本skill不会自动发信。

## 输出规模

**单刊/两刊问题**：结论、适配依据、关键硬条件、主要风险和下一步即可。

**完整选刊**：使用 `templates/selection-report.md`，通常给3–6个真正有依据的候选；可更少，不补位。先给建议，随后放可回查的依据、未决项与重要排除。至少让用户看出“为什么首投不是另外一本”。

完整任务默认附 `templates/light-write-brief.md`。用户明确只要选刊表时，可把交接压缩为表后的几条写作定位，不强制生成文件。

## 与 light-write 的接口

本轮检查的本地 `light-write` 使用以下实际接口；移植或安装版本变化时重新查看：

- `light-write/references/journal-adaptation.md`：精确venue、文章类型、投稿阶段、官方硬要求与编辑建议分离。
- `light-write/references/module-routing.md` 与 `light-write/modules/catalog.json`：任务→领域/证据形态→体裁→章节→精确venue。
- `light-write/references/integrity-and-evidence.md`：研究事实、引文和主张边界。

这些是兼容说明，不是必需依赖。移植后让接收方从实际安装位置查找，不硬编码 `D:\Light-Science\light-write`，也不假设存在目标刊专用模块。当前本地写作skill没有内置精确venue profiles；不得虚构。

交接简报应做到：

1. 明确目标的**决定状态与依据**。用户已指定/已委托代选时直接继续；只是模型建议则标暂定，无需为整理简报反复求许可。
2. 附可写的研究事实与不可越界的主张。提供原始材料路径/位置，不用选刊摘要替代全部研究证据。
3. 解释读者、论文类型、主贡献、证据顺序与哪类背景需要展开，不直接模仿目标刊某篇文章的表达。
4. 官方硬要求每条有URL、访问日期、适用类型和阶段。观察到的文章模式和写作建议单独列，不把惯例写成政策。
5. 给出有科学意义的最小改动：重排背景/论证、补清定义、解释贡献；新增实验/分析列为待办，不能写成已完成。
6. 保存可比论文和参考文献的核验状态。可比论文不是正文必须引用的清单，不要求堆砌目标刊引用。
7. 备选改变的是读者与重点还是仅格式？给接收方说明，避免准备三套全文。目标改变时重核相关要求。

这个brief是**便携研究交接材料**，不是修改另一个skill的模块、注册目录或系统配置。完整执行用户已要求的本地输出，无需额外批准；真实投稿、发信或付费不由此brief授权。

## 可选JSON证据包

仅在反复更新或有审计价值时使用 [证据包契约1.1](packet-contract.md) 和 `templates/selection-packet.json`；字段与兼容说明只在该契约维护。简短聊天不强制填表。新包明确绑定期刊、文章类型与出版路线，并分开记录作者决定和证据就绪。旧1.0保留兼容警告，不自动认证。

脚本输出 `eligible / conditional / excluded` 及推荐所缺证据，检查所列本地研究文件的哈希。不推荐任何刊的诚实草案也可返回0，不能把它解读成“已经找到首投”；来源真实、科学适配和排序仍由实际阅读与判断支持。续作、分析更正及 Memory/Workflow 回传见 [项目接入](project-integration.md)。

检查命令与验证范围：

```text
python <skill-root>/scripts/audit_selection.py <run-dir>/selection-packet.json
python -m unittest discover -s <skill-root>/tests -p test_*.py
```

完整交接前人工复核：来源是否真正支持结论；版本/身份/路线是否对应；近期先例是否真的可比；未决项是否影响首投；简报有没有把建议写成作者决定，或把计划写成结果。JSON通过不能替代这些判断。
