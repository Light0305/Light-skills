# light-visio-diagram

## 项目目录与续作

需要落盘或继续已有项目时，先读 [项目目录约定](references/project-layout.md)，按其中的本阶段位置、版本与关联规则保存；用户指定路径和旧项目优先。包内资源相对本 skill，研究产物相对真实项目，二者不要混用。只做局部讨论时无需初始化目录。

目标是交付能继续编辑的科研示意图，并说明它在视觉、科学关系和可编辑性上的实际完成程度。用户给定参考图时，以该图作为布局依据；`light-diagram-prompt` 的生成结果也可直接作为输入。

由总入口 [light-diagram](../SKILL.md) 调用时，先读取案例的 [共同交接记录](../references/routing-and-handoff.md)：复用已选参考、科学 brief、标签、关键关系和修正清单，核对来源哈希；不要自行重新生图或换参考。使用本工具的专用 scene 和实际原生检查，将最终文件、预览及分开的检查证据回写交接。直接指定 Visio 的请求可独立执行，不强制先走提示词和生图。

持续项目先查有关 Memory，再打开原论文/设计/分析及采用的稿图版本核对；记忆摘要不替代原件。直接调用时也保留科学来源定位、FIG/修订身份、已知错误与编辑边界。换版复核受影响的场景、原生文件、导出和科学关系，将采用版本与图注/术语变动交回 Write/Review，并给 Memory 有来源的决定和未决问题；简单修图不强制创建完整交接。

## 判断 Visio 是否适合

方框、流程、泳道、模块架构、设备连接和规则通路优先采用原生形状、文字与连接线。复杂组织、分子表面、写实器官等可以采用局部栅格组件，但必须逐项说明其可编辑范围。不要把整张参考图作为页面背景后声称完成复现。

当前附带的渲染器支持规则二维图形、闭合多边形、折线、三次贝塞尔曲线与闭合自由轮廓；不支持自动识图、富文本公式和局部栅格嵌入。需要这些能力时，使用可用的 Visio 工具或扩展渲染器，并相应调整检查；不要伪造支持情况。蛋白质纹理、写实光照等应另评估，原生渐变只能近似其质感。

## 从参考图建立场景

1. 实际查看参考图，记录原始尺寸、来源和 SHA-256，复制一份到本次输出目录。文字、节点、容器、装饰线和有方向关系的连线分别盘点。尤其检查交叉处究竟相连还是仅仅跨越，以及箭头的具体落点。
2. 原图复现与科学修正分开。默认按图复现；发现疑似科学错误时记录依据，必要时查原论文。用户未指定模式时，可提供复现页与明确标记的修正版。不要默默改动原图，再把它称为忠实复现。
3. 按原图像素坐标手动建立场景，先定容器与节点，再定端口、路径和文字。坐标从左上角开始。关系箭头用 `edges`；核酸骨架、括号、边框等用 `paths`，其中实体几何仍需核查连续性和身份。分支使用小型透明 `junction` 节点，让每条关系边拥有实际可粘附的两个端点。不要仅凭线段看起来接触就认定粘附已建立。

使用脚本前读 [场景格式与执行方式](references/scene-format.md)。已完成的具体样例是 [Transformer 场景](evaluations/2026-10-30-transformer/scene.json)，它是人工测量的测试案例，不是通用自动识图器。

涉及不规则轮廓、链连续性或多层遮挡时，读 [自由曲线与分子图复现](references/freeform-reconstruction.md)，并参考 [CRISPR 场景](evaluations/2026-10-30-crispr/scene.json)。场景的默认绘制顺序不适合所有图片；被骨架遮住的标注圆点应使用明确的 `draw_order` 放到上层。

涉及斜视特征平面、多级 encoder–decoder 和放大模块时，读 [张量与密集架构图](references/tensor-architectures.md)，并参考 [MonoFormer 场景](evaluations/2026-10-30-monoformer/scene.json)。非矩形对象的包围框边中点可能落在可见轮廓外；按实际像素落点反算归一化锚点，不机械复用矩形端口。

## 原生绘制和交付

有精确控制形状、路径、粘附和页面尺寸的 Visio 工具时可直接使用；否则在 Windows 桌面 Visio 中运行附带的 `scripts/render_scene.py`。依赖 Python 和 pywin32；只校验场景不需要 Visio。不得未经用户要求安装、替换或关闭其已有 Visio 环境。

```powershell
python -X utf8 scripts/render_scene.py scene.json --validate-only
python -X utf8 scripts/render_scene.py scene.json output.vsdx
```

路径相对 skill 目录解释；实际执行时改用对应绝对路径。脚本创建独立 Visio 实例，使用原生二维形状、可编辑文字和带粘附关系的一维线。输出已有时拒绝覆盖，改用新文件名。成功后保留本次保存的图供查看；不接管用户已有文档。

交付 `.vsdx`、每页 PNG/SVG、整份 PDF、场景和核查记录。保留来源与修正说明。复杂项目可另附对照页，不必机械增加交付文件。

## 实际核查后再下结论

- **结构**：保存后重开，核对标签、形状数量、每条语义线的两个粘附对象、起终点箭头样式和方向；确认 `.vsdx` 内部是否含栅格素材。文字未丢失不等于字体和排版正确。
- **交互**：选代表节点临时移动，观察连线端点是否随动，再还原；检查线不是被压平的装饰图形。多折点粘附线不保证具备 Visio 动态连接线的自动避障能力，应如实说明。
- **视觉**：打开实际导出的 PNG，与参考图按相同尺寸对照。重点看文本换行、箭头形状、交叉点、边距和路径。有差异就修改场景重导出。不要仅凭白底占比高的整图相似度声称“1:1 完美还原”。
- **科学关系**：查核实体、方向、分支及图注；科学正确性与复现忠实度分别报告。真实论文为科学核对依据，不把 AI 参考图误记成论文原图。

渲染器 `.audit.json` 的 `passed` 只代表其原生结构、文字和粘附检查通过，不代表视觉或科学检查通过。只做了场景或文档检查时，明确写“未实际渲染”。最终只报告完成的检查与仍存在的差异。
