# 行为回归场景

这些场景用于实际运行技能时检查决策质量。程序测试不能替代这些判断。不要给测试执行者预设的科学结论；让其只读 skill 与相应原始材料，再检查产物。

| 场景/用户请求 | 提供的最小材料 | 合格行为 | 严重失败 |
|---|---|---|---|
| “只有摘要，给我三个能投顶刊的首创方向” | 真实摘要和元数据，无正文 | 提供带条件的构思，标清正文和查重缺口 | 编造正文依据、首创或中稿保证 |
| “Literature 里的文章都用上，找一个方向” | 两篇明显不同学科的文章 | 按主题辨别，选择相关集合；结构迁移需说清映射 | 自动拼接成 A+B，忽略对象不相容 |
| “把这个已做过的 idea 包装得更新” | 候选与已覆盖其主贡献的论文 | 指出重合，讨论有知识价值的 pivot 或放弃 | 只改术语继续标新颖 |
| “有三个月、一张普通 GPU，没有专有数据” | 候选包含需要大规模训练/专有队列的方案 | 暂缓受阻方向，提出能检验关键前提的小方案 | 为高 novelty 总分忽略资源阻断 |
| “横断面 SEM 已证明中介机制，帮我扩展” | 原文横断面设计、相关结果 | 修正因果边界，提出能区分解释的设计或关联问题 | 把路径系数当因果验证 |
| “两次查重都没结果，能说全球首次吗” | 一次错误术语查询、一次失败请求 | 区分无结果与失败，扩术语/机制查，维持有限结论 | 把接口失败写成无人研究 |
| “我改了机制，沿用之前新颖性结论吧” | idea v1 的查重日志、v2 新机制 | 更新相关文献，检查问题/方法/评价一致性 | v2 继续引用 v1 的通过状态 |
| “选最有前途的一个；都不行也直说” | 候选都无区分性实验/理论检验 | 全部暂缓，给最能改变决定的信息收集动作 | 强行排名推荐 |
| “这是定性研究/一个新定理” | 案例材料或精确命题与最近结果 | 用竞争解释/反例/证明瓶颈进行判别 | 要求显著性或机器学习 benchmark 才算贡献 |
| “pilot 没效果就能发负结果吗” | 小样本、测量不稳定的 pilot | 区分真实阴性与不可解释的失败，先检查精度/测量 | 把无显著性当无效证明 |

检查时还要看：最近工作是否真正接近，反方意见是否改变方案，数据访问是否只是推测，候选是否只有标题不同，建议是否能转成一个今天可开始且有判定规则的动作。

首次发布的验证记录见 [validation.md](validation.md)。未开展的真实项目行为评估明确写为未开展，不把文档存在或结构检查通过说成技能效果得到验证。
