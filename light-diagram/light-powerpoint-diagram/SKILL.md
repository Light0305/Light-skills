# light-powerpoint-diagram

## 项目目录与续作

需要落盘或继续已有项目时，先读 [项目目录约定](references/project-layout.md)，按其中的本阶段位置、版本与关联规则保存；用户指定路径和旧项目优先。包内资源相对本 skill，研究产物相对真实项目，二者不要混用。只做局部讨论时无需初始化目录。

把用户指定的参考图重建为可编辑 `.pptx`。优先保证科学关系和可编辑性，再逐步逼近布局、颜色、文字与细节。输入可以是论文图、截图或 `light-diagram-prompt` 的生成结果。本 skill 负责 PowerPoint 复现；数据图或重新设计整套演示文稿使用相应工作流。

由总入口 [light-diagram](../SKILL.md) 调用时，先读取案例的 [共同交接记录](../references/routing-and-handoff.md)：复用已选参考、科学 brief、标签、关键关系和修正清单，核对来源哈希；不要自行重新生图或换参考。使用本工具的专用 scene 和实际原生检查，将最终文件、预览及分开的检查证据回写交接。直接指定 PowerPoint 的请求可独立执行，不强制先走提示词和生图。

持续项目先查有关 Memory，再打开原论文/设计/分析及采用的稿图版本核对；记忆摘要不替代原件。直接调用时也保留科学来源定位、FIG/修订身份、已知错误与编辑边界。换版复核受影响的场景、原生文件、导出和科学关系，将采用版本与图注/术语变动交回 Write/Review，并给 Memory 有来源的决定和未决问题；简单修图不强制创建完整交接。

## 先确定复现目标

1. 实际查看参考图，记录来源、图号、尺寸与文件哈希。读已有 brief、提示词和检查记录，确认每条关键关系的来源与终点。
2. 识别源图是否有科学错误，明确交付“按图复现”或“科学关系修正版”，并保留原始参考和具体改动记录。如同时交付两者，分别放页并标明。源图的不明关系不能靠漂亮连线猜补。
3. 将图拆成模块、图元、文字、装饰路径和语义关系线。斜视张量平面、残差支路和模块展开优先读 [复杂架构复现](references/reconstruction.md)。
4. 桌面 PowerPoint 可用时，尽早打开工作副本并保持可见，便于用户查看。后台批量生成只是一种执行方式；不能让用户误以为正在可见窗口逐笔绘制。只按确定的文件路径操作，保留无关文档和用户未保存的修改。

用户希望看到绘制过程时，从可见空白页逐个或分批插入原生对象，不等全部生成后才打开。可先用 Artifact Tool 制作原生图元库，再以 `scripts/draw_visible.py` 将它们逐个插入指定的空白工作文件并接回连接点。说明采用的是图元库插入，保留实际顺序记录；不要用成品显示/隐藏动画冒充绘制。

## 工具选择与制作

先确认当前主机提供的 presentations 技能和运行环境，遵守它的制作与交付规则。此包实测采用 `@oai/artifact-tool` 原生图形、显式 OOXML 连接点及桌面 PowerPoint 保存重开。可用的 PowerPoint 插件或 MCP 若能保留路径、文字和连接，也可使用，不将一个工具写成跨环境通用前提。参考工具的适用范围见 [工具研究与运行](references/tools-and-runtime.md)。

- 模块用原生形状和文本；轮廓、网格、前侧面、蛋白边界等用原生多边形/贝塞尔路径。文字保持文本对象，不描成轮廓。
- 真正需要的照片或难以自动绘制的组件可作为局部素材，单独列明来源、覆盖范围与可编辑边界。整张参考图只用于对照，不充当成品背景；整页图片或嵌入一张 SVG 不算原生重建。
- 区分物理贴近和真实连接。每条语义线需要节点 ID、连接点和方向。斜面的端点应落在可见轮廓上；包围框中点可能落在图形外。
- 折线可用连接符分段与透明拐点保留走线。分别统计逻辑关系、连接符段数、透明辅助点及可见图形；不把辅助点算作科学组件。
- 精确布局用测量坐标，保持参考画布比例。场景规范和可运行命令见 [scene 格式](references/scene-format.md)。这些脚本接收人工检查的结构，不自动识图。
- 有下标的标注使用原生文字范围；需要时用显式的 `subscript_start`。避免用下划线替代排版，也不要依靠自动缩字掩盖容纳问题。

## 必须分别验收的结果

1. **文件结构**：可打开的 PPTX、页面比例、可编辑对象、图片占比及外链。运行当前主机要求的文件检查；检查通过只证明其声明的范围。
2. **桌面行为**：在真实 PowerPoint 保存并重开。核对文字、箭头、连接节点和连接点；临时移动模块后检查端点随动并恢复。明确实际测试范围。可用 `scripts/verify_powerpoint.py`，默认可见，保留最终文件窗口。
3. **视觉效果**：导出每页 PNG，逐页查看文字溢出、重叠、遮挡、颜色、线宽、层级、箭头大小及裁切。用原图/导出图对照定位差异。像素误差是诊断值，不是“还原百分比”。
4. **科学关系**：独立检查主链、分支、抑制/激活、跳连、状态对应、局部放大与总图的一致性。真实连接符不能证明科学正确。

发现问题应修复、重新导出并查看受影响页面。不要把“文件校验通过”“真实应用已测试”“目视复查通过”合并成未经限定的全面通过，也不要承诺 1:1 完美还原。

## 交付

给出最终 PPTX、每页预览、可选 PDF、参考图/场景/来源记录和简短评估。说明对象与连接是否可编辑、局部素材或纹理近似、源图修正及尚未测试的行为。源文件与关键迭代保留在案例目录；最终文件单独放 `output/`，内部构建文件放 `.build/`。

已实测的复杂案例见 [MonoFormer 评估](evaluations/2026-10-30-monoformer/REPORT.md) 与 [交互对照](evaluations/index.html)。该例证明当前机器上这一路径可运行，不代表全学科成功率。

可见逐对象插入的初步试验见 [CRISPR-Cas9 记录](evaluations/2026-10-30-crispr-live/REPORT.md)，覆盖闭合轮廓、RNA/DNA 曲线和剪切缺口；用户认为重复且不足够复杂，因此不能作为全新复杂案例的验收结果。

用户进一步要求的全新生图与复杂可见重建见 [锂硫电池案例](evaluations/2026-10-30-lis-complex/REPORT.md)。该例从新提示词和内置生图开始，分批向可见 PowerPoint 插入四区域原生对象；粒子数量和纹理不表示测量或原子结构。
