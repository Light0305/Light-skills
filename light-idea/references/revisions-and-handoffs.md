# 新证据、想法修订与续作交接

适用于 0.2.0；依然使用 schema_version 1.0。脚本提供一致性约束，科学内容、真实查重和实际核对仍由宿主完成。

## 先判断什么需要改变

| 新情况 | 首先核对什么 | 对 Idea 的处理 |
|---|---|---|
| 找到最近工作覆盖主贡献 | 对方实际范围/版本，重合是否由正文支持 | 保留碰撞依据，缩小、改变问题/机制、转为有价值的复制或停止 |
| 有效分析挑战核心前提 | 输入、实现和分析是否有效，结论适用哪些条件 | 修订候选和预测；新问题对应的文献与反例重新查 |
| 数据/实现出错，指标异常 | 实验或分析的具体错误及受影响结果 | 先交回对应层次修复，不能据此宣布科学想法失败 |
| 现有设计不能区分解释 | 观测是否在竞争假设下给出同样预测 | 交给 Design 改判别方案；若问题本身不可识别再修改 Idea |
| 数据或预算条件变化 | 最小验证是否仍能开展，哪些条件实际确认 | 调整范围/次序或 hold，写出下一条最有价值的信息和重启条件 |
| 只改标题、润色措辞、调整状态 | 科学问题、机制、范围和判别方案是否真的未变 | 保留有效查重；不为了改文字重跑全部检索 |

阴性结果先区分“与主假设不同”“与竞争解释也不同”“测量/执行无效”“精度不足”。先确认材料有效性，再据其信息改变问题。复制、理论和定性研究按其知识贡献和判别方式处理，不能为了通过流程伪造新方法或显著性。

## 保存真实演变

一个 `Idea/IDEA-...` 可比较多个科学候选 I01/I02；这是研究取舍的工作区，候选不等于承诺产出多篇论文。

实质修改时保留原候选内容的可定位副本，例如 `versions/I01/v01.json`，再增加 version 并在 `history[]` 记 previous_version、trigger_paper_ids、changed_facets、reason 与旧版位置；保留旧证据与检索记录。合并候选时记录原 ID 与理由，原条目可 archived，不抹去淘汰路径。新版本仅复用仍适用的证据，并逐项检查问题、机制、评价和资源的一致性。

目录工具不会自动修改 I01 的科学 version。下游已有 Design/Experiment/Analysis 时，返回具体采用版本和受影响前提，让有关层次确认是否新建版本/批次；不得只改 Design 中的选择字段来冒充已重新论证。

## 证据对应实际来源

本地 `evidence.jsonl` 在实际阅读核对时记录 `source_file` 和小写 SHA-256 的 `source_sha256`；可从未漂移的 context.input_files 对应记录获取，独立来源可使用当地的文件指纹工具。`verified=true` 仍只表示宿主核对了位置和表述，不是科学认证。

核对变化时保留原文件或明确的旧版引用，复读受影响段落/图表，再决定证据是否还成立。不能仅更新哈希或 verified 让错误消失。`verify` 检查提供的证据哈希，也检查证据文件是否明显属于已知的另一篇论文。

网页证据可用 `source_url`，保留版本/日期、实际访问范围与定位，必要时保存合法来源快照。脚本不联网，不能检测远程内容是否更新，也不能判定同一个文件的文字是否真的支持该主张。

## 查重对应具体的科学内容

```text
python "<skill-root>/scripts/idea_bridge.py" fingerprint --workspace "<IDEA>"
```

该命令只读打印每个 idea 的 version 和 sha256，不进行搜索，也不修改日志。每条真实检索在 `idea_versions` 外保存 `idea_fingerprints`，例如 `{"I01":"<当时内容的 sha256>"}`。搜索结果与日志必须是实际完成的；取得哈希不代表已经查重。

指纹涵盖 question、hypothesis、claim_type、可选 scope、最近工作的 paper_id/overlap/delta，以及 design 的 prediction/rival_explanation/test/baseline/metric/success/falsifier。JSON 对象键顺序、最近工作排列、标题、理由说明、证据 ID、状态和预算不参与指纹。它帮助发现定义变化，不能判断任意两段文本在科学上是否等价。

推荐时要求至少两条当前 version、当前科学内容下成功且路径不同的检索。研究内容有实质变化须重审相关文献；纯措辞修改可能改变文本指纹，但不必机械重做全部搜索。若复核确认旧检索仍适用，追加一条可追溯的当前内容复核记录，明确引用旧 search_id、范围及复核理由；不修改原始日期、状态和旧绑定来伪装重新检索。无法确认适用性时保持 inconclusive/hold。

本版本没有自动“沿用旧检索”的命令；宿主应实际重新检查相关结果。两条日志和匹配的哈希也不能证明检索充分，更不能证明全球首创。

## 更新文献输入

`ingest` 对 run 的 CSV/JSONL 采用较新的筛选文件；相同时间而关键决策冲突则要求先解决歧义，两个文件都被记录。全库 manifest 明显漏条目或重复身份时停止，先核对 Literature 索引。导入所选 PDF 若与已有 pdf_sha256 不同或缺失，同样停止来源交接。

已有索引用 `--force` 刷新时，原 context 的完整字节保存在 `context-history/<sha256>.json`，新 context 中的 context_history 保留路径/指纹；idea、证据、查重和 decision 不覆盖。这个归档只保存输入索引，不是 PDF/正文备份；源材料旧版仍须按 Literature 规则保留。

新 context 反映当前输入；证据独立绑定核对过的来源，所以重新导入不能消除证据失效。`verify` 同时检查当前输入、归档字节与证据来源。当前材料尚未复核时不能维持相应推荐。

旧记录可继续以 candidate/hold 等状态读取；缺少源哈希会提示。旧 recommended 若没有本地来源哈希或当前内容的查重绑定，会明确要求核对补齐；不静默补写或宣告有效。只有实际核对仍成立的部分才迁移。

## Design、Memory 与 Leader

- **给 Design**：选中 idea_id/version、采用的研究问题与主张类型、最近工作差异、事实/推断/未知、证据与来源、竞争解释、最小验证、资源条件和限制。原生 ingest 复制有关记录为设计草稿，不能代替准备度或研究判断；尚待查证的方向也可以作为明确标注的草稿交接。
- **给 Memory**：本次选择/否决/修订的理由、被挑战前提、失败教训、剩余条件和重启依据，引用原生 ID、版本与具体来源。恢复时先查这些决定是否仍适用。新事实推翻旧记忆时按记忆工具的 supersedes/失效机制记录，不能把旧记忆当永久结论。
- **给 Leader**：本轮已完成范围、实际产物/版本、结构检查与科学限制、未决问题和最有价值的下一步；按原因返回 Literature、Idea、Design、Experiment 或 Analysis。仅需要长期协调时才维护 Workflow；这里没有自动调度或后台执行器。
