# 完整底稿、连续交存与统计

## 可重复的流程

1. 确认本次软件版本、模块范围和源码来源。扫描整个范围；依赖、生成物、文档、数据、测试
   默认不直接加入程序底稿，但保留候选/排除记录。特殊 DSL、模板、SQL、Notebook 人工复核。
2. 编辑 `selection.json`：每个候选写 `include` 或 `exclude` 与真实理由。按入口、核心流程、
   数据处理等合理顺序排列**完整程序底稿**。不能只挑“看起来像核心”的少数文件而遗漏其余
   自有实现，再将这个集合冒充整个软件。缩小范围必须确实是在登记可独立表达的软件部分。
3. 设置 `scope_reviewed: true` 并写 `scope_note`，记录范围及第三方处理依据。
   这是内容审核记录，不要求用户逐文件批准。`snapshot_sha256` 必须对应当前 inventory。
4. 抽取前核对每个文件哈希、路径和可读性，扫描疑似凭证/私钥；失败不输出含秘密的源码包。
5. 抽取保留原始文本、缩进和注释。仅去掉纯空白行作为本工具的保守分页约定；不以正则
   删除注释或 docstring，避免损坏字符串和版权信息。保留原始行/单元定位及文件哈希。
6. 先生成完整逻辑页，再由页选择得到一般交存节选；映射保存在 `source-pages.json`。

## 页与行：避免几种混淆

稳定规章依据见 [规则与来源](rules-and-sources.md)。内置默认**每页 50 个非空原始程序行**，
不是 50 个显示折行，也不是伪造代码填满页面。末页不足时保留真实结尾并单列核验依据；
适用的末页/有图例外来自当次指南，不能把工具默认当作规章的新条文。

- 完整逻辑底稿 < 60 页：提交全部，不往前后卷各塞一份制造重复。
- 完整底稿 ≥ 60 页：取前 30 和后 30 页，避免重叠；恰好 60 页时全部保留一次。
- 提交页连续编号 1–N，底稿原页码另存映射。不插入“省略说明页”或代码封面增加提交页数。
- 代码行不因文件名标题、页眉、页码、显示折行而增计。前后接续关系按完整底稿核对。
- 文件边界优先通过排序自然呈现；一般连续分页可以切到函数内部，不能为“完整函数”随意
  丢行跳页。结尾应尽量对应真实程序/模块结束，是否符合当次指南由人工复核。

本工具以每个源文件的 `splitlines()` 统计原始物理行，以非空原始行统计材料行；两项都报告。
Notebook 只抽取代码单元，以 `cell_index` + 单元内部行号追溯，不把 JSON 序列化行数、输出
和 Markdown 算成程序行。统计量基于整个已审核登记范围，而不是提交的节选；最终表单需核对
当前源程序量口径。没有跨语言语义解析时，不声称“去除全部注释后的有效代码行”。

## 敏感信息与第三方来源

内置扫描是定位提示，覆盖常见私钥、云密钥和硬编码凭证，不是完整安全审计，也不把内容回显
到报告。命中只有路径/行号/规则名。检查命中行区分真实秘密、环境变量读取和占位符。
示例假阳性可在 `secret_allowlist` 登记具体文件、原始行号、规则及非秘密理由，不接受通配。
真实秘密不能靠 allowlist 消音；先在真实项目按既有开发权限修复并重新冻结快照，或核对适用的
例外交存/封存方式。不能只把材料里的密钥换成星号还声称与真实源码相同。

默认不跟随符号链接，不读取项目根目录外内容；多仓库项目需分别明确范围再合并，不能借
相对路径越界。输出目录自动排除，避免把上次材料重新当成源代码。未知编码、过大文件、
未读目录或 Git 忽略项需记明处理，不得把“未读”当作统计值为零。

## 例外交存

一般交存和第十二条的机密覆盖、前 10 + 任意连续 50、目标程序加源程序等方式不能混搭。
内置脚本只实现一般交存，不自动遮盖秘密或生成例外版本。用户提出保密/例外时，先确认适用
方式、连续范围和实际办理要求，再专项整理；明确一般交存工具不支持该方式。

## 排版检查

内置代码 PDF 每个逻辑行对应一条正文行，使用真实字体度量按页缩放；若最长行在最小可读
字号仍装不下，明确失败，不能裁切、截断、省略或通过折行虚增计行。
长行可在真实开发流程中按用户授权做等价格式整理再重新冻结，或改用经核验的版式工具。
DOCX 使用同一页映射，但阅读器可能替换字体或重新分页，因此仍要在实际 Word/WPS/LibreOffice
中核对。不能以 DOCX 的显式分页符数量证明实际渲染页数；PDF 与 DOCX 内容和实际页数分别查验。
